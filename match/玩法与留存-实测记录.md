## 一、这一轮最值钱的三个数

| 量的什么 | 结果 | 它推翻了什么 |
|---|---|---|
| 一局能消掉多少颗灵石 | **35–49 颗**，摊到单色 **6–11 颗** | 同伴 need 是 34–46 → **一局根本充不满** |
| 64 关里有几关是 6 色 | **7 关**（46/47/53/54/55/62/63） | 梓的主色是第六色 → **其余 57 关他一颗充能都收不到** |
| 灵器 90 天能攒多少 | 休闲 **234 件** / 重度 **684 件** | 无上限 → 一件到手毫无重量 |

前两条合起来是一个**致命 bug**：第 32 关才解锁的同伴，大招是个摆设。
这类问题人工试玩极难发现——谁会正好选梓、又正好留意到进度条一动不动。

**方法**：把纯逻辑引擎在页面里直接驱动（`buildBoard`/`findMove`/`swapPieces`/
`settleBoard`），拦 `clearCells` 的返回值统计。不碰 UI，几秒钟跑上百局。

**边界**：贪心机器人不会用灵器、不放大招、**炼成特殊灵石实测为 0.0/局**。
所以绝对值不能当玩家数据看，有意义的是**相对形状**和**六人之间齐不齐**。

## 二、同伴充能怎么定的

### 旧算法为什么不行

只累加主色（`colors[c.col]`）。六色盘上平均每次消除只有 1/6 有效，
一局主色 6–11 颗 vs need 34–46 —— 差三到五倍。

### 新算法

```
任何消除        0.4 / 颗
主色再加        0.6 / 颗   （合计 1.0）
炼成特殊灵石    +4 / 颗
清掉机关        +2 / 个
```

**机关那条是关键**：机关关里同色灵石本来就少，不给这条的话
**越是需要大招的关卡越充不满**，正好反了。

### 主色缺席怎么补（踩过的坑）

梓在 5 色关没有主色。第一版写成「全色按 0.6 补」，实测他每局 **1.17 次**、
别人 0.63 次——从「永远放不出」直接跳到「最强」，两头都不对。

正确做法是按**一色的份额**补：`tot / 关卡色数 × 0.6`。
改完六人齐平到 **0.63–0.67 次/局**。

自检第 24 条盯着这个「齐不齐」，极差超过 15% 就报错。

## 三、被动技能：一条改掉的和一条砍掉的

| 同伴 | 随身被动 | 备注 |
|---|---|---|
| 狼先生 | 开局先给一颗疾风灵石 | |
| 钧 | 岩壳与石笼每次多褪一层 | |
| 麒 | 墨封每次多褪一层 | |
| 晰 | 每关多 2 步（限时局多 5 秒） | |
| 晓 | 连锁到 4 时随机炼一颗疾风 | 只在**第一次**到 4 时给 |
| 梓 | 开局墨封与岩壳各褪一层，**每种最多 5 处** | 上限是实测后加的 |

**梓那条实测太强**：不设上限时把第 22 关的 16 块墨封一次清空（那关墨封都是单层），
等于白送通关。被动是帮一把，不是替玩家打。

**原计划给梓的「猫铃降行减半」前提不成立**：查下来猫铃根本不会自己降行，
是靠重力和玩家交换下去的。设计前先读代码，别照着想象写。

开局类被动**必须走 `bumpGoal` 记账**，否则玩家看到盘上少了一层、数字却没动。
但**不能碰目标数本身**——`reconcileGoals` 已经按实际布上的数量对好账了。

## 四、灵器：封顶与提醒

封顶 **9 件/种**，溢出折 **120 灵力/件**（正好流进典藏册）。
发放**优先给没满的那种**，否则运气差的人会一直收到满仓那件、白白折钱。

提醒的判定（自检第 25 条把七种情形全锁住）：

| 情形 | 提不提 |
|---|---|
| 剩 2–5 步、完成度 <72%、手里有灵器 | **提**（一关只提一次） |
| 完成度 ≥72%（眼看要过） | 不提 |
| 剩 >5 步（还早）／只剩 1 步（提也没用） | 不提 |
| 手里没灵器／限时局／本关已提过 | 不提 |

**比漏提更伤的是每关都弹。** 这条的验收标准是「不唠叨」，不是「提得全」。

## 五、失败局与每日目标：来自调研的两条判断

调研了 Royal Match / Candy Crush / Homescapes / Toon Blast，两个结论直接决定了做法：

1. **头部三消刻意让失败页一无所获——因为那是它们卖复活的收银台。**
   本作永不收费，没这个包袱，所以**反着做**：失败按完成度给灵力，
   完成度 ≥80% 走「就差一点」专用文案，并把「还差 3 个 · 已完成 87%」说具体
   （原来只说「还差 1 项目标」，玩家判断不了值不值得再来）。

2. **三消品类的每日任务其实是稀缺品**（头部大多只有登录礼），做扎实反而是差异点。
   所以「今日三桩」的三条硬规矩是：**输了也算数**、不能刷新、不做倒计时压迫。

明确**没抄**的（调研里标为纯变现机制）：体力/生命值、付费复活、
限时打折与 FOMO 倒计时、付费通行证轨、断签付费修复。

## 六、本周矿脉：为什么是「首挖记榜」

第一版写的是「取历次最佳」。改成**只有第一把算成绩**，因为：
肯重开二十次的人必然压过只打一次的人，**比的就成了耐心而不是手艺**——
而这个玩法的全部意义是同一副盘比手艺。之后无限重开当练习场。

种子必须**贯穿整手**（不只铺初盘）。这是聚会赛踩过的坑：只种初盘的话，
第一次消除之后补位就各走各的随机流，两个人下同样的步子结果照样分岔。

**矿脉拓片**用 ■▨◆□（Geometric Shapes 区段）而不是 emoji：全站禁 emoji，
且这几个字形在微信、iOS、安卓、桌面是同一个样子，不会变成彩色小图。
纯文本还有三个好处——群里粘贴不吃图片压缩、不吃截图裁切、**输了也发得出去**。

## 七、矿脉榜「上传不了」的排查过程

先排除后端：`curl` 与浏览器实测 `/gf/board`、`/gf/submit` 都 200，
真实提交能写库出名次；CORS 未命中白名单时回 `*`，是宽松的。
延迟方面减掉本机沙箱 ~1.7s 代理开销（`cloudflare.com` 自己也要 1.69s）后，
worker 基线≈0、提交的 D1 耗时约 2 秒。

查出两处：

1. **没起名的玩家得不到任何提示**。上传要求先有化名，但大厅只写
   「看看别人挖到哪了」。玩家打了半天发现榜上没自己 → 结论是「上传不了」，
   其实压根没开始。
2. **弱网的 400 被当成永久拒绝**。被截断的 POST 会让后端回 `400 bad json`，
   那是网络问题不是玩家问题，而原代码一律 `stop=true`，整个会话不再上传。
   现在只有玩家改得动的（化名违规/保留词）才停。

另外量了服务端化名正则 `^[一-龥A-Za-z0-9·\-_ ]{2,12}$`：
**30 个真实风格的名字里 20 个会被拒**（带标点、带表情、单字、扩展汉字）。
客户端有同一套前置校验挡着，所以不是当前故障原因，
但意味着玩家起名时会反复碰壁——**要不要放宽需要改并部署 worker，待拍板**。

因为复现不了玩家的网络，加了**自助诊断**：三段连通性各自计时（「慢」和
「不通」要分得开），输出可复制的报告。

## 八、90 秒周榜：为什么换榜、怎么发奖（2026-08-11）

旧 90 秒榜是永久历史最佳。它有两个问题：

1. 新人面前永远是累积了很久的高分，单局竞技的公平优势没有真正发挥出来。
2. Worker 里的 `GF_CAP.rush=500000` 原本是反作弊技术闸，真人突破后却把真实成绩静默截断；
   客户端显示本地真实值，榜上却永远只有 500,000，形成了“破纪录但榜不认”的反馈断层。

现行方案：

- 榜页明确分成 **90 秒·历史** 与 **90 秒·本周** 两个入口。历史榜直接读 `gemfall.best_rush`，没有迁移也没有清表；本周榜北京时间每周一换榜，当周只取每人单局最佳。
- 历史最佳永久保留，继续用于矿灯段位、名片与个人破纪录反馈；换榜只换本周名次，不改本机与服务端的终身最高分。
- 配速员不进资源周榜。这不是去掉它们，而是让“界面上的名次”与“真实可领奖名次”完全一致；
  它们继续在无资源奖励的长期闯关榜与 90 秒历史榜里发挥追赶参照作用。
- 前三奖励直接复用已有资源，不新建三种奇异匣子：
  第 1 名典藏匣 3＋星屑 180，第 2 名典藏匣 2＋星屑 100，第 3 名典藏匣 1＋星屑 60。
  差别足够可感知，又不增加新背包字段、开匣规则与说明负担。
- 奖励不计矿力，避免前三领奖后下周又获得竞技数值优势。服务端按周封榜，客户端按周去重，
  同一响应被重放也只入行囊一次。
- `score/rush/mv` 的技术安全闸统一提到 18,999,999，`lv` 与 `chain` 同步审计；
  服务端断言直接验证 712,345／765,432／900,001 不被截断，超极端脏数据仍会被压回安全闸。

## 九、灵脉战境：用质变取代又一个短时赛（2026-08-11）

单人 60 秒新模式被撤下的原因不是数值没调好，而是它仍然在“给一段时间，看能打多少分”上做变体，与 90 秒矿灯争抢同一种心智。新模式必须改变决策结构，而不是换一个秒数。

现行灵脉战境的核心：

- 一趟一条命，无计时，每层都是首领；行动用尽仍未击破即整趟结算，没有续挖、复活或引路晶。
- 开局先选一项强化，每击破一位首领再三选一；攻势、余力、先手特殊石、护路、灵技回响等会叠到整趟结束。持久强化全满后，佳／月／诺改给只作用下一层的补给，避免长局出现无效选择。
- 六位同行统一开放，主动与被动完整生效；但连战不提前点亮主线首领徽记、未解锁人物成就，也不用肉鸽连锁抬高主榜技巧线。零步退出不计累计局数与到场天数。
- 首领身份与行动方式才是花样：叶王三相外，新加鹦鹉教授、航、音；还引入佳、月、诺三位援护人物作为强化路线。六张图均从现有世界观资源复制，源文件不改。
- 世界榜先比已击破层数，同层再比下一位首领进度，还相同才比整趟战果。击破首位后才入榜；第一位的未完成进度仍保存在本机，界面会明说还差多少。
- 服务端用独立 `gf_boss_best` 表保存一整趟词典序纪录，层数、进度、战果、强化组合与同行成对替换，不给事故敏感的 `gemfall` 主表加列，也不进矿力公式。

入口与榜单同步按同一心智收束：大厅只把「远征 · 无尽」「矿灯 · 90 秒」「灵脉战境」列为三条主玩法，聚会赛与本周挑战退到辅助层。所有排行统一进入「排行榜」，先分远征、90 秒、战境、阵营四类；90 秒类内再切历史最高与本周排行。这样既保留永久纪录与每周机会，也不会让五个等权页签挤成多行。

验证证据：前端 155 项自检全绿，Worker 榜单输出安全与配速员 15 条不变量全绿；390×844 安卓触控与 820×1180 iPad 均完整走通“选人、开局选强化、首领登场、击破过层、再选强化、败退结算”，无横向溢出与控制台错误；iPad 另验证 reduced-motion。首页三条入口、排行榜两级切换与战境返回大厅另做真实点击验收。

## 同伴平衡实测（2026-08-05）

王老师反馈「狼先生有点弱，前三个男角色雷同」。跑数据之后发现表象之下是**结构性问题**。

### 一、被动失效率 —— 这才是「带谁都一样」的真因

用真实 `levelDef()` 跑 364 关（主线 64 + 无尽 300）：

| | 主线 1–64 | 无尽 65–164 | 无尽 165–364 |
|---|---|---|---|
| 光板关（无墨封无岩壳） | 39% | 38% | 37% |
| **钧** 被动失效（无岩壳） | **69%** | 67% | 67% |
| **麒** 被动失效（无墨封） | **56%** | 55% | 54% |
| 梓 被动失效（两者皆无） | 39% | 38% | 37% |
| 狼 / 晰 / 晓 被动失效 | 0% | 0% | 0% |

**钧的被动在三分之二的关卡里根本不存在。** 而且这两人的充能还部分依赖机关
（每清一层 +2），所以在光板关是「被动失效 + 充能变慢」双重挨打。

比例在 364 关里高度一致 → 不是主线的偶然，**任何「清机关」类被动都有这个天花板**。
以后设计被动，第一个要回答的问题是「那 38% 的光板关怎么办」。

### 二、大招次数（每关平均，按每步约 4.2 颗消除估）

| 伙伴 | 每关次数 | need |
|---|---|---|
| 晰 | 3.13 | 34 |
| 钧 / 麒 | 2.80 | 38 |
| 梓 | 2.66 | 40 |
| **狼先生** | **2.53** | 42 |
| 晓 | 2.31 | 46 |

晰最强不奇怪：步数是万能资源，need 又最低。
狼先生倒数第二，且他的大招是「锦上添花」型（没攒特殊石就只能靠兜底的 2 颗）。

### 三、顺带查出的两个实现问题

1. **钧的被动描述与代码不符**：写着「岩壳与石笼每次多褪一层」，
   但石笼是 `0/1`、一次命中就清零，**根本没有「层」可褪**，破笼那行也没有 jun 判定。
   这半句是空的，他比宣传的还弱。
2. **57/64 关只有 5 种颜色**，而梓的主色是 5 号星屑 —— 他在 89% 的关卡里拿不到主色加成。
   （之前用 `tot/nc` 做过补偿，根子仍在。）
