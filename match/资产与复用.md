# 灵石远征 · 可复用资产清单

这个项目沉淀下来的东西，哪些能直接搬去做下一个作品。按「拿走就能用」的程度排序。

## 一、可以整段搬走的代码

### 1. 纯逻辑三消引擎（最值钱）

`match/index.html` 里 `[ 纯逻辑引擎 · PORTABLE CORE ]` 那一段，约 320 行。

**零依赖**：不碰 DOM、不碰 Canvas、不碰任何平台 API。棋盘、三连判定、特殊灵石炼成、
组合技、重力与斜滑、死局判定与重组、64 关关卡生成——全是纯函数与纯数据。

丢进任何 JS 运行时都能跑。本次就把它抽出来在 **macOS 的 JXA**（`osascript -l JavaScript`）里
跑了几千局无头模拟来调平衡，一行没改。

搬走的方法：从 `/* ---------- 随机 ---------- */` 抽到渲染层横幅之前，
剥掉 `PLAT`/`AU`/`SFX` 三个平台对象，再补几个渲染层替身即可（脚本见下）。

### 2. 无头模拟器（调平衡的工具）

`scratchpad/sim*.js` —— 驱动纯引擎跑完整关，统计通关率。
本次靠它发现：第 3 关因为收集目标要一种盘上不存在的颜色而**永远打不通**，
整条 64 关主线卡死在第三关；以及猫铃章的通关率是个位数。

这类问题**人工试玩很难发现**（谁会正好去试第 3 关又正好卡住），
但模拟器几分钟就能扫完 100 关。做任何关卡制游戏都值得先建这个。

### 3. 美术资源映射表（`ART` + `art()` + `applyArt()` + `drawArt()`）

约 50 行。作用：**插画没到位时游戏照常能玩**，图丢进目录就自动生效，源码一行不改。

- `art(key)` 画布版，返回 Image 或 null
- `applyArt(el,key)` DOM 版，支持 `data-fit` / `data-pos`
- 缺图静默回落到程序化绘制，失败只请求一次不重试

**踩过的坑**：`background-size` 必须内联写。ID 选择器里的 `background` 简写会把
类规则里的 `cover` 重置掉（ID 特异性更高），结果 512px 立绘在 44px 框里按原尺寸
从左上角显示，只看得到一块空白。

### 4. 上传管理器（`LB.flush`）

约 60 行。**串行 + 指数退避 + 抖动 + 多入口唤醒 + 永久性错误停重试**。

适用于任何「本地有成绩、要传到后端、网络不可靠」的场景：

- 串行：同一时刻只允许一个提交在飞，重入排队而不是丢弃
- 退避：20s→40s→80s… 封顶 5 分钟，带 ±20% 抖动（避免一个班几十台同时重连造成同步冲击）
- 六个唤醒时机：开局 / 通关 / 联网恢复 / 切回前台 / 打开榜单 / 退避定时器
- `pagehide` 用 `sendBeacon` 兜底（必须发 `text/plain`，`application/json` 会触发预检而信标发不了预检）
- 400 类永久性拒绝停止重试并把原因显示给用户，不做无意义的无限重试

### 5. 世代号模式（`GS.epoch`）

治「异步结算链作用到已经换掉的场景」这一类 bug 的通用办法：
每次换局/重开/交棒时 `GS.epoch++`，长链条在每个 `await` 之后核对，过期就自己退出。

本次一个改动同时修掉了三个表现完全不同的 bug（快赛交棒串局、暂停重开串盘、末次连锁被吞）。

## 三、方法论（下次少走的弯路）

### 让机器去发现「不可能」

三个最严重的 bug 都是「某个目标永远达不成」，而且**表现都是玩家卡死、不是报错**：

1. 第 3 关：收集目标要一种盘上不存在的颜色
2. 第 51 关：石笼落在岩壳上被静默丢弃，但 need 已经算进去了
3. 第 42 关：猫铃降行后挤掉了石笼

根因是同一个：**目标数量靠预测，而不是按实际布上的数量对账**。

最终解法：建盘之后统一 `reconcileGoals()`，`need = 盘面真有的数量`。
这一类 bug 到此为止，以后加新机关也不会再犯。

配套：自检里加一条「1–100 关每个目标都能在盘面上真正达成」，
**建盘之后清点，而不是拿 need 跟它自己的来源比**（旧版那条是恒真的同义反复，什么也抓不到）。

### 审查超大单文件要切片

直接让 agent 读 190KB 的单文件 HTML 会反复 stall（Workflow 跑两次都卡死）。
可行的做法：

1. 按注释横幅把文件切成带**原始行号**的片段丢进 scratchpad
2. **冻结一份快照**再交给 agent —— 否则你一边改它一边读，它会因为行号漂移而反复重读直至超时
3. 用普通 Agent 并行审，别用 Workflow（并发一高就更容易撞上 API 错误）

四轮对抗式审查共确认并修掉 **40+ 个真 bug**，其中 1 个致命、9 个 high。

### 平衡不要靠感觉

无头模拟器跑出来的数字才是依据。本次弱 AI 平均通关率从 22% 调到 51%，
每一步调整都有前后对比。但也要认清模拟器的边界——
它不会用灵器、不会放大招、不懂「在铃那一列炼竖向疾风」这种技巧，
所以**绝对数值不能当玩家通关率看，有意义的是相对形状**（哪一章明显塌陷）。

## 四、跨平台

见 `PORTING.md` 与 `match/ports/`。要点：网页版继续作为正式源 →
Capacitor 8 独立副本上 iOS/Android → 微信**小游戏**（不是小程序）的无 DOM Canvas 版本。

当前微信 v0 已验证平台壳、触摸、Canvas、存储与美术同步，但只移植基础三消。
正式 64 关内核虽有清晰的 `PORTABLE CORE` 区段，仍引用少量网页全局状态与特效容器；
下一步应先把这些依赖变成显式注入，再复用，不要直接复制后宣称“零改动”。

跨端目录的复利点：

- `shared/resource-catalog.json`：任何新平台都可读取的资源清单
- `wechat-minigame/scripts/sync-assets.mjs`：美术只维护一份
- `ios-capacitor/scripts/sync-web.mjs`：网页更新后可重复生成 iOS 副本
- `tools/verify-ports.mjs`：防止副本漏图、哈希漂移和微信包体超预算
