## 二、美术系统怎么工作（动手前必读）

### 资源映射表 `ART`

`match/index.html` 顶部有一张 `ART` 表（搜 `const ART={`），56 个槽位，**当前零缺图**。
按文件名把图丢进 `match/art/` 就自动生效，**源码不用改**。

三个取图函数：

| 函数 | 用途 | 缺图时 |
|---|---|---|
| `art(key)` | 拿 Image 对象 | 返回 null |
| `applyArt(el, key)` | 贴成 DOM 背景图 | 静默回落到字形徽章 |
| `drawArt(ctx, key, x, y, size)` | 画进 Canvas | 返回 false，调用方走程序化绘制 |

**缺图永远不报错**，游戏回落到程序化绘制。所以换图是安全操作。

### 现有资源盘点

56 张 / 2.04MB，四档规整尺寸，各 14 张：

| 尺寸 | 用途 | 例 |
|---|---|---|
| 1024×448 | 横幅／章节大图 | `chapter-1` … `chapter-8`、`win`、`lose`、`lb-banner`、`party-banner` |
| 512×512 | 人物立绘 | `ally-wolf`、`ally-jun`、`ally-qi`、`ally-xi`、`ally-xiao`、`ally-zi`、`boss-ye`、`boss-she` |
| 384×512 | 典藏册卡面 | `card-vista-1..8`、`card-ink`、`card-cage`… |
| 256×256 | 棋盘贴图／道具 | `gem-0..5`、`gem-orb`、`ob-ink`、`ob-crate`、`ob-cage`、`ob-bell`、`box-*` |

最重的一张 80KB，整体不需要减重。

### 四个已经踩过的坑，别再踩

1. **`ob_*` 和 `card_*` 是两套，不要弄混。**
   `ob-ink` 等五张是**棋盘格子贴图**（墨封就是一块方形墨迹），铺格子好看、当卡面只是一块纹理；
   `card-ink` 等是同题材的**竖版卡面**。棋盘用 `ob_*`，典藏册用 `card_*`，两套并存。

2. **`applyArt` 的 `background-size/position` 必须内联写。**
   `#ally-badge` 这类 ID 选择器里的 `background` 简写会把类规则里的 `cover` 重置掉（ID 特异性更高），
   结果 512px 立绘在 44px 框里按原尺寸从左上角显示，只看得到一块空白。

3. **图片 load 回调必须按元素挂，不能在共享 Image 上打标记。**
   标记挂在共享 Image 上、闭包只捕获第一次渲染的那个元素，
   于是「动态重建 + 冷加载」的网格（典藏册 32 张卡）重建后新元素永远拿不到回调，卡面一直空着。

4. **典藏匣两张图必须同尺寸方形**（`box-closed` / `box-open` 靠换 `background-image` 原地切换）。
   实测两图匣体底边偏差 0px、左边 1px，容器尺寸不变就不会跳。

## 三、美术上真正的机会在哪（我观察到的，供参考）

资源本身很干净，所以**机会不在补图或减重**，在下面这些：

### ① 浅色主题下，灵石立绘的「预烘光晕」会露馅 ★ 优先级最高

2026-08-05 刚重做了浅色主题（详见第五节）。改完之后发现：
部分灵石／宝珠的 webp 里**烘焙了柔和的白色外发光**。
深色底上它读作「宝石在发亮」，非常好看；
**浅色底上它读作一圈脏兮兮的奶白色雾**，大厅顶部那排灵石尤其明显。

可选解法（你判断哪个好）：
- 重出一版去掉预烘光晕的灵石图，发光改由代码画（Canvas 已有 `fxRing`／`fxBurst` 可复用）
- 或保留光晕，但在浅色主题下用 CSS `mix-blend-mode: multiply` / 降低不透明度压掉
- 或出「浅色专用」一套，`ART` 表按主题切 key

### ② 特效目前全是程序化的，有提升空间

`fxBurst` / `fxBeam` / `fxRing` / `fxMark` 都是纯 Canvas 画的（搜 `function fxBurst`）。
2026-08-05 刚补了**顿帧、震屏递进、边缘泛光**（第五节），手感层面的骨架有了，
但**视觉层面**还可以更好：碎屑、光轨、特殊灵石炼成的瞬间。
如果你要加贴图特效，走 `ART` 表加槽位即可，缺图自动回落。

### ③ 商店新商品完全没有视觉

刚上线的「矿场 · 兑」有 22 件商品（题名／题跋／落印三类槽位商品），
目前**纯文字列表**，一张图都没有。这是最缺美术的地方。
落印（seal）尤其适合做成线稿印章图形。

### ④ 「封样」层需要一个视觉

矿力 78k 以上的三层商品未解锁时显示为「封样 · 甲/乙/丙」，
现在只是文字加点线框。做一个「盖着布的货架」或「封蜡」的线稿会好很多。

### ⑤ 名片与拓片是全站最值钱的展示位

`矿工名片` 可导出成图片发微信群，是玩家唯一会主动传播的东西。
现在是 Canvas 手绘的（搜 `名片`），排版和质感都还有空间。

## 五、我这轮（2026-08-04 ~ 08-05）刚改了什么

**这些都已上线，请在此基础上工作，不要回退。**

### 玩法与数值

- **矿力重标定成三条线 + 均衡奖**：深度（走多远）／技巧（打多险）／勤勉（来多勤），
  总分 = 三线之和 + 3×最短那条。所以「补短板」的收益是四倍，
  肝帝与技术流各有各的赛道。
- **四座**：深度／技巧／勤勉／**运数**首座，摆在矿脉榜顶部。
  **一个人可以四个座全占**（王老师定调「只要能肝就一定有回报」）。
  运数 = 开匣开出的臻卡数，3% 掉率、跟投入完全无关，是留给新人的窗。
  空座显示「虚位以待」——现在运数正是空的。
- **三阵营**（光明／黑域／灰塔）改吃上面那三条线，各有除数；拉锯条加了滚动 7 天窗口。
- **矿场 · 兑**：九层货架按矿力门槛解锁，**矿力是门槛不是货币，兑换不扣矿力**。
  货币是灵力与星屑。含封样、本期矿口（每期三件七折、全服同一份）、
  兑窗月配额（每月 6 扇）、首兑戳。
- **岁记改成年轮**：做成一桩就刻一轮，不再「差一桩整月空手」。
- 贴身对手、明牌配速员、赛季幽灵。

### 视觉与手感（和你直接相关）

- **浅色主题重做**。诊断结论和直觉不同：文字对比度当时全部合格，
  坏的是**表面分层**——`edge on panel = 1.31`（描边需 ≥3.0）、
  `panel on bg = 1.15`（图底分离），明度全挤在 L\* 85–96。
  重排后阶梯为 bg2 78.2 → bg 83.7 → edge 57.8 → panel2 92.5 → panel 97.3，
  每一对都用 WCAG 重算过。
  **改任何一个浅色变量都要重算对比度**，别凭眼睛调。
- 修了 **gold2 在两套主题里角色相反**的问题（深色下它最亮，浅色下却最灰）。
  现已统一为「gold 是底色、gold2 是强调」。
- 修了**矿坑三色没在浅色里覆盖**（白天玩，米色页面中间嵌一块纯黑棋盘）。
- **「不可用」在浅色下不能靠降透明度**：面板本就比页面亮，半透明后仍是更亮的斑，
  锁着的反而比能点的抢眼。浅色下改成压到页面之下 + 内阴影，读作凹槽。
- **连击手感**：顿帧（3 连 40ms → 封顶 130ms）、震屏随连锁递进（2.5px → 9px）、
  边缘泛光。**顿帧只冻画面，不冻限时局倒计时**——冻住就是作弊，这条有自测钉死。

## 六、动手规矩

1. **自测必须保持全绿。** `window.__selftest()` 返回 `{total, failed, lines}`，
   当前 **101 条**。加功能请一并加断言；**断言别写成同义反复**
   （踩过：把 `weekNum()` 埋在函数里，测试改存档期号根本没换期，
   「连查 60 期」实际是同一期查了 60 遍）。

2. **改完 `index.html` 必须重新生成 Service Worker**，否则缓存版本号不变，
   装过 PWA 的玩家一直吃旧代码（表现是「代码改了但不生效」，极难往缓存上想）：
   ```
   node match/ports/tools/build-service-worker.mjs
   ```
   （王老师那台 Mac 没装 node，仓库里还有一份等价的
   `match/ports/tools/build_service_worker.py`，两份输出逐字节一致。你有 node 就用正本。）

3. **网关白名单有正副本两份**：正本 `deploy/gateway/api/`，副本 `match/edge-functions/api/`。
   **改正本再 `cp -R` 同步**，主页构建有守卫会拦下不一致。

4. **`match/ports/` 是你的地盘**（CI 工具链、微信小游戏、iOS Capacitor 壳、CHANGELOG）。
   我不动那里，除非修 CI 红。

5. **别动的地方**（我在维护，改动会撞车）：
   - 矿力公式（`pwLines` / `pwTotal`）与服务端 `gfDepth/gfSkill/gfGrind`——**两边必须逐字一致**
   - `leaderboard/worker.js` 的写入链路
   - 商店经济（`GOODS` / `SHELF` / `SHOP_QUOTA` / `CAMP_DIV`）
   - **加 D1 列必须同时改七处**：建表／ALTER 迁移／INSERT 列／VALUES 占位／UPDATE／bind／
     **回读的那条 SELECT + merged 映射**。漏最后一处出过线上事故：
     `undefined × 160 = NaN → 写进库变 NULL → 玩家矿力归零`，**且没有任何报错**。

6. 本地起服务：`python3 -m http.server 8753`，然后开 `http://localhost:8753/match/index.html`。
   **PWA 缓存会顽固地喂旧代码**，测试时加 `?bust=时间戳`，必要时手动 unregister service worker。
