## 发布门禁

每次修改必须至少执行：

1. `node monkey/tools/extract-assets.mjs`
2. `node monkey/tools/extract-assets.mjs --check`
3. `node deploy/monkey/build-edgeone-monkey.mjs <新的 /tmp zip 路径>`
4. 浏览器打开 `?qa=1`、`?partyqa=1`、`?stress=1`
5. 390 × 844、320 × 568、1280 × 720 检查横向溢出、主流程和猴先生完整可见
6. 多人至少实测设置、交机、限时结算、同轮种子一致、排名和刷新续赛

### 2026-08-12 · Claude · 修「成绩海报里还是金鱼」——SW 装了旧 HTTP 缓存

- **现象**：鱼小姐改青绿并发布后，游戏内立绘确实变青了，但**成绩海报里那条鱼还是金的**。
- **不是没改干净**：仓库、发布包都验过零金色（把 zip 解开取图标，泡泡区域全是 `#3fab84`/`#6cd0af`）。
- **真因**：海报会把 app 图标 `icons/monkey-100-512.png` 整个画进左上角（`loadPosterIcon`），
  而 `sw.js` 安装时用的是 `cache.addAll(CORE)`——**它走浏览器自己的 HTTP 缓存**。
  EdgeOne 给图片设了长缓存，于是新版 SW 把旧的金鱼 PNG 原封不动装进了新缓存。
  页面 HTML 是导航网络优先所以是新的，图标却是旧的，**版本号明明升了、资源却是旧的**。
- **修法**：安装改成逐个 `fetch(new Request(url,{cache:'reload'}))` 再 `cache.put`，绕开 HTTP 缓存。
  缓存版本升到 `-10`（已经装了 `-9` 但里面是脏资源的人，需要一次新的安装轮）。
- **自鸣棋早就修过同一个坑**（见其协作日志 0810「网络加固」那条：安装时用 `cache:'reload'`
  防止新 SW 搭配旧 HTTP 缓存）。同一个生态里踩两次，所以这次把它写成门禁：
  构建期断言 `sw.js` 里必须出现 `cache:'reload'`，拿掉就构建失败。已反向验证。
- **教训**：判断「改没改上线」不能只看页面，要看**那个资源自己是怎么被缓存的**。
  导航网络优先 ≠ 所有资源都新；恰恰是这种混合策略最容易造出「一半新一半旧」的现场。

### 2026-08-13 · Claude · 暂停与返回主菜单、称号系统、红鲤鱼帽

**暂停（本次最容易做错的一件事）**

- 这个游戏所有的限时效果——磁卡、宽容尺、电梯欠条、金猴、审讫红边、房租台、泡泡台、
  多人赛倒计时——记的都是 `performance.now()` 上的**绝对时刻**。所以「停掉 rAF」根本不是暂停：
  时间照走，暂停十秒等于白送十秒道具时间和十秒比赛时间。**真暂停 = 恢复时把所有绝对时刻整体后移**。
- 三张登记表 `PAUSE_TIME_FIELDS` / `PAUSE_PLAYER_TIME_FIELDS` / `PAUSE_ENTITY_TIME_FIELDS`
  列出所有要后移的字段，`PAUSE_NON_TIME_FIELDS` 列出名字像但不在这条时间轴上的（米数阈值、`pausedAt`）。
  **以后新加任何 `xxxUntil` / `xxxAt` 字段，必须登记进去**，否则：
  - 构建期：`build-edgeone-monkey.mjs` 静态扫源码里所有以 Until / At 结尾的字面量键与登记表对账，漏一个就构建失败；
  - 运行期：`?qa=1` 的「暂停计时字段登记齐全」扫活对象，同样抓。
  两道门都反向验证过（删掉 `magnetUntil`、新增一个没登记的 `coffeeUntil`，都被当场拦下）。
  注意门里写死的是「一个都不许漏」这条约束，不是「一共几个字段」那种会过期的镜像。
- `?qa=1` 另有「暂停会把所有绝对计时整体后移」一条：真跑一次 pause/resume（可传假时钟），
  断言剩余时长分毫不差，做完把动过的字段还原。故意让 `shiftDeadlines` 漏移，它会 FAIL。
- 顺带补上一个旧漏：原来 `visibilitychange` 只停 rAF、不停计时，切后台十秒回来照样白送十秒。
  现在切后台走同一条 `pauseGame()`，回到前台停在暂停面板上，由玩家自己点继续。
- 返回主菜单要二次确认（同一个按钮点两次），避免手滑丢进度。多人赛里这个按钮改成
  「结束本轮并交接」，走正常 `finishRun('timeout')`，**不允许直接跑回首页**——否则这一轮悬着、后面的人没法接。

### 2026-08-13 · Claude · 手机全屏（大屏手机上下留边）与红鲤鱼帽重画

**「加到桌面启动不是全屏」的真因，不是 PWA 声明，是一个写死的高度**

- 声明其实一直是齐的：`apple-mobile-web-app-capable`、manifest `display: standalone`、
  `viewport-fit=cover`、`env(safe-area-inset-*)` 都在。问题出在 CSS：
  `#gameShell{width:min(100vw,460px);height:min(100svh,844px)}`。
  那个 **844 是 iPhone 13 / SE 时代的屏幕高度**，写死之后就成了一份会过期的镜像。
- 实测（Chromium 真跑，不是估算）：

  | 设备 | 视口 | 上下留边 |
  |---|---|---|
  | iPhone 15 | 393 × 852 | 8px |
  | iPhone 15 Pro Max | 430 × 932 | **88px** |
  | iPhone 16 Pro Max | 440 × 956 | **112px** |
  | Pixel 8 | 412 × 915 | **71px** |

  而且露出来的是 `#d9ccb1`（桌面「手机框」外的底色），和纸色 `#faf3e2` 不同，所以特别显眼。
- **修法**：`@media(max-width:699px)` 下铺满 `100vw × min(100svh, 100vw*2.5)`，去掉左右黑边与投影，
  底色改成纸色。`≥700px` 的桌面手机框造型原样保留。
- **顺带发现**：现代手机的长宽比几乎正好是本作的设计比 844/390 = 2.164——
  iPhone 15 Pro Max 是 932/430 = 2.167。**铺满之后反而比原来封顶时更不变形**
  （原来 Pro Max 上是 -9.3% 的纵向压缩，现在是 +0.2%）。那个 844 封顶是纯粹的损失。
  2.5:1 的收口只对超长安卓设备生效，那种情况下露出来的边也是纸色，看不出来。
- 三个安卓宽虚拟视口的兜底路径（`html.wide-mobile-viewport`）必须保持固定盒再整体缩放，
  所以给它加了一条更高优先级的规则把固定盒还回去，别被铺满规则带偏。已实测 980×2048 下外框仍是 960×1761。
- **iPhone 上还有一个不是代码的坑**：只有 **Safari** 的「添加到主屏幕」才产生独立全屏应用；
  Chrome / Edge / 微信内置浏览器加出来的只是书签，点开仍带地址栏，用户会以为是游戏没做全屏。
  安装说明页现在第一条就写这句，并且检测到 iOS 上的非 Safari 浏览器时会直接点破。
- 四条门禁已加并反向验证：铺满规则本身、PWA 全屏声明、安全区声明、安卓宽视口固定盒。
  改回 844 封顶、删掉任一条声明，构建都会失败。

**红鲤鱼帽重画**

我上一轮加的「自检入口必须被调用」断言写的是 `html.includes(fn + '(')`——
**被函数定义自己满足了**，把三个自检的调用点全删光照样出包。
修的时候又踩第二层：改成数带括号的调用仍然不对，因为 `setTimeout(runQA,50)`

**以后加门禁，一律当场反向验证一次**：故意把它该拦的东西弄坏，看它是不是真的红。
这一条现在是本作的硬规矩，本次新增/修改的每一道门都照做了。

### 2026-08-13（夜）· Claude · 一个假 bug 的三次误判，比真 bug 更值得记

排查报上来一条「高」：**传真科的台子一踩就碎、碎了不再生，摔回去就永久卡死——
既上不去也摔不死，这一局永远不结算**。听起来完全说得通（fax 台确实是落地 150ms 后 `alive=false`，
而 `generatePlatforms` 只往上加、不补下面），我差点就动关卡生成器了。

**它是假的。** 我查了三次才查对，三次错法各不相同，都值得记：

1. **第一次：用例自己造出了游戏里不存在的状态。** 我把猴子瞬移到 610 米再手动
   `generatePlatforms`，25 局里「卡住」1 局。可 `resetWorld` 之后世界是从 baseY 长出来的，
   瞬移打乱了路线锚点——那个洞是我自己挖的。
2. **第二次：判据选错了字段。** 改成正常开局，用「`maxMeters` 连续 25 秒不涨」当判据，
   30 局里中了 2 局。但 **`maxMeters` 只增不减**：玩家从峰值掉下来、正在往回爬，
   这个数当然不涨——那是正常游戏，不是卡住。
3. **第三次才对：判据要看「当前高度在一段时间里的活动范围」。** 24 秒窗口内上下活动
   不到 25 米才算卡住。结果：**30 局 0 卡住**，最窄的活动范围也有 26 米，中位 712 米。

顺手把「那两局到底怎么回事」也算清楚了：站在那一带任意一块台上弹起来，
实际还够得到高出 300~396 的台（靠香蕉板/险字台的高弹力）；seed 29 那局头顶最近的台
干脆只高出 103——**普通一跳 136 就够得着**。所以既不是死路，连难都算不上。

真正的原因是**自动驾驶的搜索窗口写死 158**，而各类台的弹力换算成升高是：
普通 680->136、险字 825->200、审讫 930->254、香蕉板 955->268。窗口比实际能跳到的还矮，
于是它看不见高弹力的台，站在原地干弹。我试着按最高弹力把窗口放到 275 再量了一次：**40 局中位高度 2081 -> 2113，其余指标基本不动**——
是噪声不是改进。所以**撤回了**，代码维持 158，只把结论写进注释。
不为一个不影响结果的小别扭去动 `?stress=1` 依赖的代码，这也是一条：
**改动要有量出来的理由；量完发现没用，就撤掉，别留没根据的改动。**

**给下一个接手的三条**：
- **自动驾驶卡住 ≠ 关卡有死路。** 下结论前先算一遍「从这一带任意一块台弹起，够不够得到更高的台」。
- **判据用错字段，比没有判据更能骗人。** 单调只增的量（`maxMeters`、累计计数）不能用来测「有没有停滞」。
- **能在真机复现 ≠ 复现的是真问题。** 用例里手动改 `state`、瞬移角色、跳过生成流程，
  都可能造出游戏里根本达不到的状态。这也是这次排查里给证伪方写的那条要求：
  「特别注意：用例里自己制造了不可能的状态，就说游戏有问题」。我自己先踩了。

这两条是排查里报上来、我判断**属于既有问题而不是这次改动引入**的，也没有独立复核过

### 2026-08-13（深夜）· Claude · 结算导航改人性化（附一条形同虚设门禁的现场）

王老师原话：「那个下一页下一页，在一些场景中，比如结算还有主页问题上不够灵活……
我们的确限制在一个屏幕、不要上下滚动，但是目前这个会不够人性化在部分习惯性场景」。

**先量，再改。** 量出来的事实比「翻页手感不好」严重得多：

| 视口 | 结算卡片高 | 屏高 | 卡片外空着 | 三页内容合计 |
|---|---|---|---|---|
| 390x844 | 384 | 844 | **460px** | 885px |
| 320x568 | 355 | 568 | 214px | 829px |

也就是说：**屏幕空着近一半，内容却被切成三页盲翻**。分页当初是防溢出加的，
但没人量过到底有没有溢出。（三页合计 885px 确实塞不进一屏，所以分页本身没错，
错的是「用线性翻页去导航三个互不相同的页面」。）

**更硬的一条：结算页根本没有回首页的路。** 穷举过结算上所有可点的东西——
再来一局（直接开局）、生成成绩海报、登记、查看世界楼榜 / 称号墙 / 奶茶图鉴、上一页、下一页——
没有任何一条能回到 `#titleScreen`。而开工装备、本局轮值、档案章数、添加到桌面
全都只长在首页上。**玩过一局之后，这些东西就再也够不着了，除非重新载入页面。**
`showTitleScreen` 全仓库只有四个调用点，全都进不来结算这一屏。

**改了什么**

- 上一页/下一页 -> 三个命名标签（成绩 / 本局档案 / 登记收藏）。
  线性翻页的毛病不是慢，是**把去处藏了起来**：玩家不知道下一页有什么，就没有理由点。
- 标签红点：这一局真解锁了东西才亮。**第一版写坏了**——判据用「teaOrder 有没有字」，
  而它每局都有字（没开出新的也会写一句「没开出新的」），于是红点每局都亮。
  **一个永远亮着的红点等于没有红点**，玩家两局就学会无视它。现在用 `state.freshTeaCount`。
  「登记收藏」的点只在还没登记过化名时亮——登记过之后正式局是自动补交的，再催就是噪音。
- 左上角「返回首页」，与右上角编号牌对称，**不占任何竖向空间**（这一屏竖向预算紧，
  回家的路不该跟内容抢地方）。它必须清 `state.over`，否则子屏幕的返回键会把玩家又弹回结算。
- 再来一局 / 生成成绩海报移到三页共用。核心循环是「摔了再来」，这颗按钮不该会消失。
- 页码点：占的是原来「1 / 4」那一格，**不新起一行**。第一版让它单独占一行，
  320x568 上把奶茶图鉴顶出去 26px——一个纯便利功能不该拿走内容的高度。
  页数超过 `DOT_PAGER_MAX`（6）退回文字，否则中间那一格会被撑爆。
- 左右滑动、左右方向键都能翻页，全部走同一个 `stepPage`。
  两套写法迟早出现「滑得到第 4 页、按钮只到第 3 页」。
  滑动只挂在菜单屏上（游戏进行中它们是 hidden，`activePager()` 返回 null，不抢操作手感）。
  **实测过一个风险**：从「再来一局」按钮上横滑会不会既翻页又开局？用 CDP 发真触摸事件测的，
  横移 120px 后 Chromium 取消了 click，没有误开局。所以没加「不许从按钮上起滑」的限制——
  加了反而会让手势在按钮密集的下半屏失效。
- Esc 改走统一的 `activeMenuClose()`。原来那里手抄了三个子屏的判断，安装页与分享页漏在外面。
- 子屏返回文案说实话：从结算进去的写「返回本局结算」，不再谎称「继续上楼」。

**320x568 满档案时首页溢出 40px（真 bug）**

根因不是屏幕小，是**卡片高度会随档案内容增长**：`称号 · 专业坠落员（MYSKME 认证）`、
`在喝 · 红鲤鱼冰萃（仿的）` 这种按钮文案一换行就多一行。改成单行截断，
再补一段 `max-height:620px` 的收紧。**卡片是 `overflow:hidden`，溢出的部分不是能滚，
是直接看不见**——玩家只会觉得「最高分那一行没了」，不会觉得「有东西被裁了」。

**这一次最值得记的：一条形同虚设的门禁，让所有人都以为查过了**

原来守「单屏不滚动」的自检写的是：

```js
getComputedStyle(el.title).overflowY==='hidden' && typeof renderPager==='function'
  && document.querySelectorAll('.result-page').length===3
```

三个恒真的条件。**当场反证**：往首页卡片里塞一个 4000px 的空 div，卡片溢出 3822px，
这条自检照样绿。所以 Codex 报「桌面与手机逐屏实测溢出均为 0」不是他测错——
是这条门根本没在守它声称守的东西，而 320x568 满档案那 54px 就这么漏过去了。

现在改成真量：拿**最坏情况的档案**（全称号、全奶茶、最长的称号名与奶茶名、意外与窗景收满）
逐屏逐页量 `scrollHeight - clientHeight`。空档案量不出问题，这也是原来漏掉的原因。

**门禁分两层，各管一段**：构建期（CI 会跑）守结构，运行期 `?qa=1` 守行为。
这次新增/改动的每一道门都做了反向验证，其中数引用次数那条**连踩两层**：

1. 第一版写 `/data-page-step/`，被自检自己的 `querySelector('[data-page-step]')` 满足了。
   改成匹配真正的属性写法 `data-page-step="`。
2. 改完再数 `bindSwipePaging` 的引用次数，又被自检里的 `.toString()` 那句满足了——
   把真正的接线整行删掉，门照样绿。**修法：数之前先把自检代码整段切掉，只数产品代码。**

判据留在这里：**检测器和检测目标同形，就是一道假门。**
加门禁一律当场反向验证，而且要验「删掉接线」这种最像样的破坏，不要只验「删掉函数」。

**顺带修好了自己的验收脚本**

`play.mjs` 与 `tea-test.mjs` 从 PR 41 分页那天起就一直是红的，没人发现——
它们直接点 `#resultTitlesButton`，而那颗按钮在结算第 3 页、默认 `display:none`。
先拿 Codex 未改动的 `20260813.8` 跑了一遍确认同样红，才敢说不是本次改动引入的。
**一套会静默过期的验收脚本，和一条不会失败的门禁是同一类问题。**
现在两个脚本都改成按命名标签走位，顺带也就测到了新导航；
奶茶那条改成翻遍所有页再数杯子（原来在一页上数 20 个，分页后当然只有 4 个）。

### 2026-08-13（深夜）· Claude · 世界楼榜的退出键会被别人的化名裁掉（并加多视口验收）

并行巡查报上来的一条「高」，**在真机上是死路**：

320x568（iPhone SE 一代 / 5s）打开世界楼榜，只要榜上任何一行的化名到了 8 个字以上，
行就换成两行，五行一起把卡片顶爆 51px。卡片是 `overflow:hidden`，
**被裁掉的正好是「看完了，继续上楼」那颗唯一的退出键**——而手机上没有 Esc。
玩家只能杀进程或刷新，刷新前本局的登记入口也一起没了。

三个点特别值得记：

1. **触发条件不是自己造成的。** 化名上限就是 12（`#rankName maxlength`），
   只要**别人**填了长名字，所有小屏玩家一起中招。自己怎么玩都躲不开。
2. **桌面上永远测不出来。** 电脑有 Esc，而且 1280x720 根本不溢出。
3. **跟首页那两颗按钮是同一条病**：卡片高度随内容增长。
   首页是自己的称号名/奶茶名变长，榜单是别人的化名变长，根因一样。

**改了什么**：榜单行的化名与来源改成单行截断；另外给榜单补了一颗角落返回键
（和结算那颗同款），因为**唯一的出口不该是卡片里最后一个普通流内子元素**——被裁了就等于没有。

**这条暴露了我自己那道新门禁的两个洞，两个都补了**

- **洞一：漏了屏。** 我写的 `measureMenuOverflow` 只量了首页、结算、称号墙、奶茶，
  **没量世界楼榜**。补上了，而且喂的是 12 字化名 + 三个口径各量一遍——
  行高是被别人的名字决定的，不喂最长值等于没量。
- **洞二：漏了视口，这个更要命。** 补上榜单之后，那条自检在 390x844 上**照样是绿的**，
  因为那个视口有富余。也就是说：一条只在宽屏跑的门禁，和一条永远不会失败的门禁是同一类东西。

  修法是新增 `monkey/tools/qa-viewports.mjs`：在五个视口上各跑一遍 `?qa=1`，
  任何一个红就退非零。反向验证过——把化名截断那行拿掉：

  ```
  [败] 320x568  FAIL 单屏菜单在满档案下溢出：世界楼榜(weekly) 超出 51px、(alltime) 51px、(effort) 51px
  [过] 360x800 / 390x844 / 430x932 / 1280x720
  ```

  **只有最小的那个红**——这就是为什么它以前漏得掉。

  视口清单里每一条都写了它代表什么，别当成随手挑的数字在某次「顺手清理」里删掉最小那个：
  最小那个正是唯一会出事的那个。CI 里没有浏览器，所以这一步是收工前手动跑的；
  构建门禁守结构，它守「小屏上放不放得下」。

**为什么放在仓库里而不是会话的临时目录**：上一轮的验收脚本（`play.mjs` / `tea-test.mjs`）
就躺在临时目录里，PR 41 加分页之后它们静默红了一整天没人发现。
**会过期的验收脚本，和不会失败的门禁，是同一个问题的两面。**

**顺带一条方法**：巡查 agent 发现主会话正在改 `monkey/index.html`，
自己用 `git archive origin/main` 取了一份只读快照再测，并在报告里注明哪些结论来自快照、
哪些在工作区版本上复现。多 AI 并行时这是必须的——否则「审的是哪一版」根本说不清。

### 2026-08-13（深夜）· Claude · 六方向并行验收 Codex 的 PR 37-43：21 条确认问题

做法沿用 0813 那套：六个方向并行找，每条必须在真浏览器里复现，再由独立的一组默认证伪。
12 个 agent，确认 21 条。整体结论：**Codex 这一批是扎实的**——构建、美术同步、压力测试、
对外口径都真绿。查出来的问题集中在两处：**小屏/横屏的可达性**，和**门禁的真假**。

#### 一、玩家真会撞上的死路

- **手机横过来就出不去（最严重）。** 844x390 上首页的「单猴挑战，立即上楼」整颗被裁在卡片外，
  玩家开不了局；进了称号墙/奶茶图鉴更糟——关闭键在屏外，触屏没有 Esc 的等价物。
  证伪那一组用**八条独立出路**逐个试（点卡片外各处、上滑下滑、双击、后退、Escape），
  只有键盘 Escape 有效，也就是手机上**只能刷新页面**。
  根因是 PR 41 为了「单屏不滚动」把 `.screen` 与 `.card` 两层滚动都关掉了。
  **判据：单屏是优化，不是硬约束。** 装不下时必须还够得着，否则「装不下」就变成「出不去」。
  `overflow-y:auto` 在内容装得下时和 `hidden` 完全一样（不出滚动条、滚不动），
  竖屏观感一点没变。「不需要滚」这件事改由 `measureMenuOverflow` + `qa-viewports.mjs` 真量。
- **世界楼榜的退出键会被别人的化名裁掉**（另见上一条记录）。
- **化名撞上服务端保留词（「老师」这类），客户端放行、服务端每次 400，界面却只说「待联网」。**
  队列一局一局堆上去，玩家以为网不好，其实永远传不上去。
  原因是那句真话写在 `worldSyncMessage` 里，而打开榜单会跑 `loadWorldBoard`，当场把它清空。
  修法：**故意不在客户端抄一份服务端的保留词表**——那是一份必然过期的镜像。
  客户端要做的不是猜服务端的规则，是**如实转述服务端的回答**：
  存一个不会被清掉的 `worldBlockedReason`，并且当场 toast 一次。
- **补交队列一条坏记录堵死后面所有局。** 实测第一局被退回后，后面两局一个请求都没发过。
  但也不能见 400 就丢：化名有问题时每一条都会 400，丢光等于把成绩全扔了。
  判据：先把每条都试一遍，**只有在至少一条成功过**（证明化名本身没问题）时，
  才把被永久退回的那几条单独丢掉；全军覆没就一条都不丢，留着等玩家改名。两个方向都实测过。
- **「特批夜班版」海报的二维码扫不出来**：模块色 `#fff4d5` 画在 `#fffaf0` 上，对比度 1.06:1，
  灰度只差 4/255，出现率 5.5%。根因又是「纸色写死、墨色跟着版式走」——一个常量一个镜像。
  修法不枚举例外，而是**算一遍对比度、不够就换深色**，以后新加版式自动受保护。

#### 二、门禁的真假（这一节比上一节更值得看）

巡查专门有一路去反向验证每一道门。结果：**六道门是假的**，其中两道是我当天刚加的。

| 门 | 假在哪 |
|---|---|
| 「菜单采用单屏分页且不依赖滚动」 | 三个条件全恒真，首页撑爆 3822px 照样绿 |
| 「自检入口必须被引用」 | 把 `setTimeout(runStressQA,...)` **注释掉**（而非删掉）照样绿，24000 帧压力测试静默消失 |
| 「联网出口只能有一个 fetch」 | sendBeacon / EventSource / `new Image().src` / 取别名 四种旁路全放行；反过来**注释里写一句 fetch( 会误报** |
| 「手机铺满」 | 只查第一个 `@media(max-width:699px)` 块，在后面再写一块 844 死高度就绿 |
| 「世界窗景链路」 | 只查函数定义在不在，删掉调用点后构建绿、自检绿，八景当场退化成四景死循环 |
| 「计时字段登记齐全」 | 只认对象字面量的 `键:`，`state.xxxUntil=` 这种懒创建字段一个都扫不到 |

**共同根因只有一个：拿源码字面量当程序结构使。** 于是同一句注释既能满足门禁、也能弄红门禁。
修法是一个公共工具 `stripComments()`：**数之前先剥注释**。
这里自己又栽了一次值得记：第一版写成「连字符串一起剥」，结果被正则字面量里的引号
（`/['"]/` 那种）带偏，从那个引号一路吞到很远，`CODE` 直接残缺、构建报「取不到自检代码的起点」。
**要正确地找出注释，反而必须认得字符串与正则**（`'https://x'` 里那个 `//` 不是注释）。
所以最终版是「字符串与正则原样保留、只剥注释」。

**反向验证这次做成了双向的**（`该红的红 + 该绿的绿`，11 条，全过）。
只验一个方向会漏掉误报那一半——「注释里提到 fetch( 就构建失败」这种毛病，
只测「该红的」永远测不出来。

顺带还撞到一个小的但很典型的：我新加的 `.screen,.card{scrollbar-width:none}` 让
既有门禁里 `/\.card\{([^}]*)\}/` 这个不带锚的正则先命中了组合选择器，量到了别人家的声明。
**取 CSS 规则要锚在行首**。

#### 三、我自己那道新门禁的两个盲区（都补了）

1. **漏了屏**：`measureMenuOverflow` 一开始只量首页/结算/称号墙/奶茶，**没量世界楼榜**。
2. **量的是空状态**：结算三页是在「一局都还没打过」时量的（`?qa=1` 恰好就是这个时机），
   `deathLine` / `visitedDepartments` / `freshHonors` / `teaOrder` 全空，当然不溢出。
   而**首局最容易撑爆**——新称号与新奶茶只在首次解锁时出现，档案越空越多。
   现在量之前先把这几块填成最坏内容（最长死亡台词、12 个部门全到访、4 个新称号、5 杯新奶茶）。

补完之后 320x568 / 375x553 / 360x640 三档全红，这才是它该有的样子。
修法是在矮屏上**少展示几条、不是少解锁几条**（「另有 N 个已收入称号墙」这句话本来就在，
只是让 N 大一点），外加收掉品牌块这类纯装饰余量。七个视口现在全过。

**断点只写一处**：矮屏断点从 620 提到 700（360x640 本来漏在外面），
CSS 里写 `@media(max-height:700px){:root{--compact-result:1}}`，JS 读这个变量，
不再各写一个数字——同一个断点抄两份，迟早一边改了另一边没改。

### 2026-08-13（深夜）· Claude · 只做竖屏、把翻页砍掉一半、称号改绕口令并配徽章

王老师这一轮四条要求，逐条对应：

**一、「只要竖屏模式，不要横屏」**

加了竖屏提示层 `#rotateGate`。**判据是「横着 *而且* 矮」，不是单看 orientation**——
桌面 1280x720 与 iPad 横屏 1024x768 同样是 landscape，但它们高度够，照常玩。
`max-height:500px` 这条线把「手机横过来」单独圈出来：iPhone 13 横屏 390 高、
Pro Max 430 高、常见安卓 360 高，全在线下；桌面 720、iPad 768，全在线上。实测四档确认过。

横过来会**自动暂停**，走的是和切后台同一条 `pauseGame` 通道，所以所有绝对计时整体后移，
转回来点继续分毫不差（实测：横着待 3.6 秒，磁卡剩余 19998 -> 19752ms）。

> 这里差点误判一次：第一版测的是 `state.player.magnetUntil`，那是个**没登记过的野字段**，
> 当然不会被后移，于是报「被吃掉 4360ms」。磁卡真正的字段是 `state.magnetUntil`。
> 又一次印证：**用例造错了比代码错了更会骗人**，判据字段先去登记表里对一遍。

CSS 与 JS 用的是同一条媒体查询，且有一条自检直接拿 `CSSRule` 原文比对——
抄错一个就会出现「提示层出来了但局没暂停」，这种半截状态最难查。

**二、「上一页下一页还是多」**

真正的解法不是把翻页控件做好看，是**先让页数变少**：

| | 改前 | 改后 |
|---|---|---|
| 称号墙 | 一列 4 个 / 页，**4 页** | 两列 8 个 / 页，**2 页** |
| 奶茶图鉴 | 一行一杯 4 杯 / 页，**5 页** | 三列 12 杯 / 页，**2 页**（最矮屏 9 杯 / 3 页） |

少到 2 页之后，**上一页/下一页整个撤掉**——留着只会白占一整行，还让人以为必须顺着翻。
现在四条路都比「点两次下一页」快：点页码点直达、**点列表空白处翻下一页（循环）**、左右滑、方向键。
王老师说的「再点一下再点一下自动就是下一页」就是第二条。

奶茶柜改成三列之后顺带解决了另一件事：**它现在真的像个柜子**，一眼十二杯，
比一行一行读更像「图鉴」。这就是「利用好视觉空间」那半句的落点。

台词挪进了下方的**详情条**，点一个才显示。16 条台词同时铺在两列里谁也读不进去，
摊开反而没人看；一次只读一条，读的人就真的会读。
锁着的格子也**允许点**了——原来 `disabled` 之后连「这个要怎么拿」都问不出来，等于把目标藏了起来。

> 又踩了一个自己种的：详情条第一版用了 `display:flex`，里面的 `<b>名字</b>` 变成一个 flex 子项、
> 后面的台词变成另一个，两段被并排摆成两栏，读起来整个错行。**普通文本流的地方别用 flex。**
> 是靠截图看出来的，数值断言一条都没红——「改了画面就要看画面」第三次应验。

**三、称号全部重写，五个做成绕口令职位**

id 与 `test` **一个字节都没动**（存档里存的就是 id，改名等于让老玩家的称号当场蒸发），

排版学（落在海报上）、天体/重力（做成意外事件，对比地球与月球的跳跃高度）。

### 2026-08-13（深夜）· Claude · 十二种音乐调式：第二个「各行各业的学问」

接着立面往下做的第二个领域。选它的理由很实际：**自适应音乐引擎本来就有，成本几乎为零**；
而且和建筑一样**不用翻译**，出海时不用重做。

**关键做法：保持旋律轮廓不变，只换音阶**

先把现有的三条旋律反解了一遍，发现它们本来就是伊奥尼亚（大调）——
`[12,14,16,19,16,14,11,9]` 对 `[0,2,4,5,7,9,11]` 正好是级数 `[0,1,2,4,2,1,-1,-2]`。
于是只要把级数映射到别的音阶上，**节奏、乐器、低音、强度逻辑一律不用动，变的只有色彩**。
换部门时听得出「换了个味道」，但不会变成另一首歌——这是风险最小的一条路。

有一条自检专门盯着这个前提：**拿大调代回去，必须和改版前一个音不差**。
谁改了 `MELODY_DEGREES` 或 `degreeToSemitone`，它会立刻红；否则曲子被悄悄改了没人会发现。

**十二种调式，一个部门一种**（每条 fact 是「为什么它听起来是那个味道」，不是名词解释）：

大堂宫调式五声 · 质检部伊奥尼亚 · 传真科混合利底亚 · 房租科多利亚 · 驯猴办弗里几亚 ·
冗余科全音阶 · 黑化肥蓝调音阶 · 谜题科和声小调 · 绕口令办都节音阶 · 观景台自然小调 ·
标点科平调子 · 加盖工程部八声减音阶。

**自检当场抓到一个真问题（也是这一轮最值得记的）**

我原本给谜题科放的是**利底亚**、给加盖工程部放的是**利底亚属七**。写完一量：

```
两两撞车：["lydian 与 ionian 音级集合相同","lydomb7 与 mixolydian 音级集合相同"]
```

原因：本作的旋律级数集合是 `{0,1,2,4,5,-1,-2}`，换算成音阶下标**从来不用第 4 级**，
而利底亚与大调**恰恰只在第 4 级上有区别**。也就是说这两个部门「换了个味道」是假的，
玩家听到的和大调一模一样——**而且不会有任何报错**。

判据因此定成：**不是「steps 数组不同」，而是「按旋律真正会用到的级数算出来的音级集合」不同**。
换成和声小调（增二度落在真会走到的位置）与八声减音阶（对称到没有主音，配一栋永远在加盖的楼），
重测两两撞车为 0。

**第一次到这层讲建筑，第二次讲音乐**

一次塞两条知识谁也记不住。分两次讲既不挤，又给「再来一局」多了一个理由。
判据不用另建计数器：立面在第一次就入档，所以「立面已有、调式还没有」正好等于第二次。

**顺带修了一个改版前就有的老 bug：八个音的旋律只响了四个**

换调式之后再量，谜题科（和声小调）与加盖工程部（八声减音阶）的**音程集合仍然完全相同**。
查下去发现不是调式的问题：旋律取号写的是 `bar*4 + s/2`，而旋律只在 s=2/6/10/14 上响，
`s/2` 恒为奇数（1,3,5,7），于是 `bar*4+奇数` mod 8 **永远只落在 {1,3,5,7}**——
作曲写了八个音的旋律，**有四个从上线那天起就没响过**。
而那两种调式的区别恰好落在这四个哑音上。

改成 `bar*4+(step-2)/4`，每小节推进四个音、两小节走完一整条旋律。
改完十二种音程集合两两不同（大堂从 3 个音程变成 6 个）。
这个 bug 单看代码几乎发现不了，是**量「排程器真正排出来的音」**才浮出来的。

**这一轮判据本身错了两次，比结论更值得记**

1. 第一次量「音级集合」——四个根音一混就跑满十二个音，差异全被盖住，反而显示「都一样」。
2. 改成「相对根音的音程」才对。**判据要跟着「玩家实际听到的是什么」走，不是跟着数据结构走。**

这和 0813 早些时候「用单调只增的 maxMeters 测停滞」是同一类错：**判据选错字段，比没有判据更能骗人。**
所以自检最后写成了「跑一遍真的取号逻辑，收集相对根音的音程」，而不是直接读 steps 数组。

**我判断不了它好不好听——这条明确留给王老师的耳朵。**
我能验的只有：十二种音级集合两两不同、大调精确复现原曲、音高落在 MIDI 43..67、
不报错、24000 帧压力测试照过。**好不好听是耳朵的事，不是断言的事。**

**门禁那边又踩了同一类错，这次是第三回**

「立面数与部门数必须相等」那条突然报「立面数 24」——因为我的正则
`/\{id:'…',dept:'…',name:/` 在整个 html 上匹，把结构完全相同的 `MODES` 也数了进去。
前两次分别是「不锚行首的 `.card` 正则」和「从 `HONOR_GLYPHS` 一路找 `href=`」。
**判据：扫描之前先把范围圈死，否则迟早匹到隔壁那张结构一样的表。**

还有一个更值得记的：新加的调式门禁**自己是坏的**——`deptIds` 声明在立面那个 `{}` 块里，
调式块看不见，于是抛 ReferenceError 而不是断言，干净构建也是红的。
**是反向验证抓出来的**，不然这道门会以「永远红」的形态上线，比永远绿更难查。
修法是把部门清单提到两个块之外共用——同一个清单取两次，迟早取法不一致。

### 2026-08-13（深夜）· Claude · 配色学：这一次的知识是**可校验的**

第三个「各行各业的学问」，挂在八种世界窗景上（不是部门——窗景本来就是每局抽一扇的节奏，复用它）。

**和前两个领域最大的不同：说法不是贴上去的标签，是一条被盯着的断言。**

做法是倒过来的：**先量，再写**。把八种窗景的 sky / ink / accent 全转成 HSL，
算出线条与点缀的色相差，再按通用分级（同类 0-15 / 类似 15-45 / 邻近 45-75 /
中差 75-105 / 对比 105-165 / 互补 165-180）归档：

| 窗景 | 色相差 | 关系 | 明度序（天光 > 点缀 > 线条） |
|---|---|---|---|
| 江南雨窗 | 12 | 同类色 | 89 > 65 > 40 |
| 北欧薄暮 | 4 | 同类色 | 90 > 73 > 40 |
| 丝路晨光 | 8 | 同类色 | 87 > 63 > 42 |
| 地中海午后 | **180** | 互补色 | 91 > 60 > 41 |
| 和纸月夜 | 103 | 中差色 | 90 > 61 > 38 |
| 包豪斯清晨 | 166 | 互补色 | 90 > 51 > 32 |
| 安第斯风带 | 120 | 对比色 | 89 > 52 > 41 |
| 靛蓝鼓点 | 1 | 同类色 | 91 > 56 > 34 |

地中海午后是**正好 180 度**的教科书互补，这是量出来的，不是我挑好听的说。

**两条自检，两层门**

- 「声明的色相关系与实际色值对得上」：谁改了一个 hex 让配色不再成立，当场红。
  **这是配色这个领域的全部价值所在**——否则文案会慢慢变成一句谎话。
- 「明度序：天光最亮、线条最暗、点缀居中」：八种全部成立。
  它比色相更要紧——**色相错了只是不好看，明度错了台阶就看不清**。

同一条判据在两处守：游戏里的 `?qa=1`（有人跑才拦）与**导出器**（CI 每次构建都拦）。
导出器那道也反向验证过：把地中海的点缀色从橙改成青，出包直接失败并报出
「声明的配色是互补色，实算是同类色」。

**知识落在哪：结算的「本局档案」页，只在初见那扇窗景时出现**

不是局内 toast——建筑与音乐是「你正在看/正在听」的东西，配色是要停下来端详的。
放在结算页玩家才读得进去，也不跟局内那两条抢。实测：初见时出现，同一扇窗第二次就不再出现。

**复利**：调色板连同它的色相关系一起进了总账（`palette.scheme` / `hueGap` / 三色 HSL），
做周边、卡面、说明页时可以直接照抄这三色，**也照抄它为什么成立**。
分类器本身也从正本现取，导出器不另存一份判据——游戏里、素材库里、自检里永远是同一个算法。

**又一次「范围没圈住」，第四次了**

导出器取配色工具时，`hueGap` 与 `classifyScheme` 都是**单行函数**，
我却用 `/[\s\S]*?\n\}/` 去匹，一路吞到下一个换行加右括号，把中间的 `HUE_BANDS`
一起卷了进来，拼出来的源码里它出现两次，直接 SyntaxError。
前三次分别是：不锚行首的 `.card` 正则、从 `HONOR_GLYPHS` 一路找 `href=`、
在整个文件上匹 `{id,dept}` 把结构相同的 `MODES` 也数了进去。
**判据补一句：先看清楚目标是几行，再决定用哪种匹配。**

## 2026-08-14 · 三选一改成一排任命台 / 首页收藏条 / 香蕉商店 / 排版学

四件事，一次说完。前两件回应「三选一容易分心打断」与「首页缺少这些位置」，
第三件回应「香蕉没什么用」，第四件是接着做的第四门学问。

### 一、模态三选一整套拆掉，改成「一次落点选择」

**为什么不是调参数而是拆掉**：这是心流型无尽爬楼，核心快感是不间断的向上运动，
玩家注意力全在「猴子与下一块台阶的空间关系」上。模态三选一属于另一种结构——
回合分段式 roguelike（杀戮尖塔、哈迪斯在房间边界给祝福），那些能用是因为它们
本来就有「停下来成长」的节奏。四重代价：运动回路被切断、关掉后空间感知要冷启动、
「再来一次」的冲动被打断，**最要命的第四条是选择本身没有游戏性**——
这个游戏的动词是「位置」，卡片的动词是「文字」。

替代：人事部空降一排三块干净木台，每块托一枚任命图标，落到哪块拿哪份，
另外两份当场作废并淡出（淡出很重要，直接消失的话三选一在体感上退化成「捡到一个东西」）。

**第一版是错的，量出来才知道**：最初把三份挂在「本来就存在的那一排」上。
实测关卡生成器极少一排造三块台（多数排一到两块），三选一常年退化成二选一甚至发不出去。
判据：**不要假设世界里正好有你要的形状，需要什么形状就自己造。**

不复用部门排型也是有理由的：绕口令双词牌、冗余幻影台、限时计租台都会把
「选哪块」搅浑——玩家分不清自己在选任命还是在躲坑。

自动驾驶六局实测：任命真能被捡到、能被错过（第 2 局死在 1200 米前、第 5 局发出两批只拿了一批）、
零卡死。

### 二、首页收藏条：九格图标，一眼看完长期档案

原来六种收藏挤在一行九号小字里（「意外 x/13 · 窗景 x/8 · 立面 x/12 · 调式 x/12」），
等于收集了也看不见。

**新东西要自己挣出自己的高度**：这条把原来占一整行的「称号墙 / 奶茶图鉴」
两个按钮吃掉了，入口改成点图标。「戴着什么、在喝什么」原来写在按钮文字上，
现在直接画进格子里（称号格画那枚徽章，奶茶格画那只杯子）——省掉一整行字，信息一点不少。

九条收集线：称号 / 奶茶 / 行头 / 任命 / 纸型 / 意外 / 窗景 / 立面 / 调式。
后两条是这次新加的（行头见第三节、纸型见第四节），任命也顺带进了长期档案
（只记见过、不记数值），于是一局作废的增益也有了跨局的收集线。

**图标系统改名 ICON_GLYPHS**（原 HONOR_GLYPHS）：它已经不只给称号用了，
道具、局内任命、收藏条都吃这张表。名字要说实话，否则下一个人会另起一张表，画风裂成两份。
这次新增十三枚，全部同一画布同一画风。**加一条收集线的边际成本是一行数据，不是一张新图。**

顺带修了一件早该修的：五件道具原来拿 `<text>` 画「U / @ / 免 / 梯 / 宽」五个字符，
既不是图标风格，也不能当免翻译素材导出（出海要重画），还跟「蛇蛋驴不靠文字牌解释」自相矛盾。

**放大四倍看才发现的事**：`stamp`（公章侧面）与 `tower`（三角加方块）缩到 22 像素
就认不出了——一个糊成一坨，一个像弹出符号。给任命与立面各配了专用图标。
四个「立面」候选并排试过，只有退台式高楼在真实尺寸上还认得出。
**判据：图标要在它真实出现的尺寸上认得出，不是在设计稿上认得出。**

### 三、香蕉商店：十八件行头，猴子真的穿上开上

「香蕉已入账。用途：香蕉。」这句自嘲的提示挂了很久，现在兑现了。

**三条设计原则（写在代码里，免得被改歪）**

1. **全是外观，一个数值都不碰。** 这是最省事也最正确的平衡设计：外观不进任何公式，
   就永远不会出现「买得起的人更强」。副作用是**定价可以放心地贵**——
   贵不影响任何人的成绩上限，只影响他多久能显摆。
2. **货币是已经拿到手的成绩，不是新资源。** 局内香蕉照旧计分，结算时再存进长期账户。
   花掉不回溯改分，历史成绩不可变。
3. **一件行头＝一行数据。** 每件只写一段画在猴子 100x116 坐标系里的 SVG，
   局内、货架、海报三处共用同一段。反向验证跑过整套工作流：加一行数据 + 重跑导出器，构建通过。

**定价是量出来的**：自动驾驶五局，中位 14 根 / 1696 米，每百米 0.75 根。
新手八到十根，熟练之后爬得高、又可能拿到「香蕉复利」任命，一局二三十根不难。
按每局十二根估：18（约两局）/ 60 / 150 / 340 / 750。第一档两局就能买走一件——
第一次逛不至于空手；私人电梯 750 是全作最贵的一件。**改价格前请重测收入，这是一份会过期的镜像。**

**最划算的一处改动**：整个作品的副标题是「电梯在等他。他没看见。」，
而商店最贵的一件正是私人电梯。买下之后副标题改口成「他终于看见了，并且买下来了。」
一行代码，把最长的那条收集线接回作品的第一句话。

**试衣镜按槽位拉近**：第一版画整只 52 像素的猴子，截图一看戒指手表挂绳全是几个像素，
三格看着一模一样。裁的是 viewBox 不是图形，所以仍是同一段 WEAR_ART，没有第二份预览图。

**海报（名片）印穿戴**：左上角那格原来是静态应用图标，现在换成穿好行头的猴子。
这是「攀比」真正发生的地方——海报是玩家会发出去的那张图。

素材库多了 `outfits/` 一类，导出的是「穿着这件的猴先生」整只（行头的价值在于穿上之后是什么样）。
总账 schema 升到 7，共 88 个可复用资源。

### 四、排版学：第四门学问，挂在六种海报纸型上

前三门的落点：立面挂部门、调式挂部门、配色挂窗景。排版学只能挂海报——
它是这个作品里唯一的印刷品，也是玩家会发出去、会被人放大看的那张图。

**和配色学同一条路子：知识必须可校验。** 海报原来有十四处字面量字号
（30/46/44/70/28/26/162/35/42/20/25/31/23/19/17），看着「差不多有层次」，
实际相邻级差忽多忽少（30→28 差 7%，44→70 差 59%），眼睛读不出稳定的秩序。
全部换成 1.25 等比数列（基准 16）上的十级。关键不在 1.25 这个数字，
而在**整版只用一条数列**——任意两级的关系固定下来，整版自动成体系。

六种纸型各带一条排版学（模块化比例 / 层级差 / 大字收紧小字放松 / 行长上限 /
深底浅字会「胀」/ 留白是排版的一部分），第一次抽到那种纸型时在分享页讲一遍，
之后收在收藏条的「纸型」格里随时重看。

### 五、这一轮反向验证抓到的五个真问题

**每一条门禁都双向验过**（构建 15+8+4 条、运行时 10+3+4 条）。抓到的：

1. **`declinedAt` 是 performance.now() 时刻却没登记进 PAUSE_\* 表**——暂停会白送时间。
   干净构建就红，说明我加完门禁没跑构建就去写反向验证了。「该绿的绿」是第一条该跑的。
2. **称号存档契约那道门在整个 html 上匹 `{id,emblem,tint}`**，PERK_POOL 一加 emblem 就误报
   「扫到 21 条」。同一类「范围没圈住」的第五次。
3. **「不许退回模态」那道门查的是 html**，一句提到 `openPerkChoice` 的注释就能把它弄红。
   注释既能满足门禁、也能弄红门禁，两个方向都验过才算数。
4. **「行头是纯外观」那条只穿了每个槽位的第一件**——给王冠塞跳跃加成，门照样绿，
   十八件里只查了六件。改成逐件单穿。**一条只覆盖三分之一的门，会让人以为全查过了。**
5. **「字号全在模块化比例上」是自证的**：它用 `typeStep()` 生成参照集，再检查 TYPE 的值在不在里面——
   而 TYPE 本来就是 typeStep 算的。把 typeStep 改成「第 3 级返回 33」，门照样绿。
   **判据：校验的一方不能是被校验的那一方。** 改成从 TYPE_BASE/TYPE_RATIO 独立算一遍。

另外两次「用例自己错了」也值得记：
- 破坏脚本在 `landOn` 开头写 `state.player.vy=1`，**那是空操作**（后面会用 bounce 覆盖）。
  门没红不是门的问题，是用例根本没改到东西。
- 加一件行头必然让素材库过期，那是导出器的本职，不是误报。改成验整套工作流。

### 六、又一次「只量了一半」

新加的收藏条在 320 宽上「11/20」顶出格子，而 **qa-viewports 七个视口全绿**——
因为 `measureMenuOverflow` 只量卡片的**纵向**溢出。
「一屏放得下」和「每一格看得清」是两条判据，只写了前一条等于只查了一半。补上横向测量之后，
连 390x844（设计基准）都红了。

追这件事又连撞三回：320 装不下 → 缩字号；390 装不下 → 再缩；360x800 又装不下。
最后才看明白根因：**每格的宽度取决于卡片内边距，而内边距跟着「高度」断点变**——
同一个 360 宽，640 高上装得下、800 高上就装不下。
拿宽度断点去追一个受高度影响的量永远追不完，而且追出来的每个数字都是一份会过期的镜像
（和 CLAUDE.md 里「`#gameShell` 高度封顶 844」是同一类错）。

改法：`fitCollectCounts()` 量一次，装不下就缩，缩到装下为止，下限 5.5px（再小就该让门禁红）。
以后加第十格、换字体、出新尺寸的手机，它自己就对了。七个视口全绿。
