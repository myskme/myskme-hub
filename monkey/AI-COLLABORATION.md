## 发布门禁

每次修改必须至少执行：

1. `node monkey/tools/extract-assets.mjs`
2. `node monkey/tools/extract-assets.mjs --check`
3. `node deploy/monkey/build-edgeone-monkey.mjs <新的 /tmp zip 路径>`
4. 浏览器打开 `?qa=1`、`?partyqa=1`、`?stress=1`
5. 390 × 844、320 × 568、1280 × 720 检查横向溢出、主流程和猴先生完整可见
6. 多人至少实测设置、交机、限时结算、同轮种子一致、排名和刷新续赛

### 2026-08-12 · Claude · 修「成绩海报里还是金鱼」——SW 装了旧 HTTP 缓存

- **现象**：鱼小姐改青绿并发布后，游戏内立绘确实变青了，但**成绩海报里那条鱼还是金的**。
- **不是没改干净**：仓库、发布包都验过零金色（把 zip 解开取图标，泡泡区域全是 `#3fab84`/`#6cd0af`）。
- **真因**：海报会把 app 图标 `icons/monkey-100-512.png` 整个画进左上角（`loadPosterIcon`），
  而 `sw.js` 安装时用的是 `cache.addAll(CORE)`——**它走浏览器自己的 HTTP 缓存**。
  EdgeOne 给图片设了长缓存，于是新版 SW 把旧的金鱼 PNG 原封不动装进了新缓存。
  页面 HTML 是导航网络优先所以是新的，图标却是旧的，**版本号明明升了、资源却是旧的**。
- **修法**：安装改成逐个 `fetch(new Request(url,{cache:'reload'}))` 再 `cache.put`，绕开 HTTP 缓存。
  缓存版本升到 `-10`（已经装了 `-9` 但里面是脏资源的人，需要一次新的安装轮）。
- **自鸣棋早就修过同一个坑**（见其协作日志 0810「网络加固」那条：安装时用 `cache:'reload'`
  防止新 SW 搭配旧 HTTP 缓存）。同一个生态里踩两次，所以这次把它写成门禁：
  构建期断言 `sw.js` 里必须出现 `cache:'reload'`，拿掉就构建失败。已反向验证。
- **教训**：判断「改没改上线」不能只看页面，要看**那个资源自己是怎么被缓存的**。
  导航网络优先 ≠ 所有资源都新；恰恰是这种混合策略最容易造出「一半新一半旧」的现场。

### 2026-08-13 · Claude · 暂停与返回主菜单、称号系统、红鲤鱼帽

**暂停（本次最容易做错的一件事）**

- 这个游戏所有的限时效果——磁卡、宽容尺、电梯欠条、金猴、审讫红边、房租台、泡泡台、
  多人赛倒计时——记的都是 `performance.now()` 上的**绝对时刻**。所以「停掉 rAF」根本不是暂停：
  时间照走，暂停十秒等于白送十秒道具时间和十秒比赛时间。**真暂停 = 恢复时把所有绝对时刻整体后移**。
- 三张登记表 `PAUSE_TIME_FIELDS` / `PAUSE_PLAYER_TIME_FIELDS` / `PAUSE_ENTITY_TIME_FIELDS`
  列出所有要后移的字段，`PAUSE_NON_TIME_FIELDS` 列出名字像但不在这条时间轴上的（米数阈值、`pausedAt`）。
  **以后新加任何 `xxxUntil` / `xxxAt` 字段，必须登记进去**，否则：
  - 构建期：`build-edgeone-monkey.mjs` 静态扫源码里所有以 Until / At 结尾的字面量键与登记表对账，漏一个就构建失败；
  - 运行期：`?qa=1` 的「暂停计时字段登记齐全」扫活对象，同样抓。
  两道门都反向验证过（删掉 `magnetUntil`、新增一个没登记的 `coffeeUntil`，都被当场拦下）。
  注意门里写死的是「一个都不许漏」这条约束，不是「一共几个字段」那种会过期的镜像。
- `?qa=1` 另有「暂停会把所有绝对计时整体后移」一条：真跑一次 pause/resume（可传假时钟），
  断言剩余时长分毫不差，做完把动过的字段还原。故意让 `shiftDeadlines` 漏移，它会 FAIL。
- 顺带补上一个旧漏：原来 `visibilitychange` 只停 rAF、不停计时，切后台十秒回来照样白送十秒。
  现在切后台走同一条 `pauseGame()`，回到前台停在暂停面板上，由玩家自己点继续。
- 返回主菜单要二次确认（同一个按钮点两次），避免手滑丢进度。多人赛里这个按钮改成
  「结束本轮并交接」，走正常 `finishRun('timeout')`，**不允许直接跑回首页**——否则这一轮悬着、后面的人没法接。

### 2026-08-13 · Claude · 手机全屏（大屏手机上下留边）与红鲤鱼帽重画

**「加到桌面启动不是全屏」的真因，不是 PWA 声明，是一个写死的高度**

- 声明其实一直是齐的：`apple-mobile-web-app-capable`、manifest `display: standalone`、
  `viewport-fit=cover`、`env(safe-area-inset-*)` 都在。问题出在 CSS：
  `#gameShell{width:min(100vw,460px);height:min(100svh,844px)}`。
  那个 **844 是 iPhone 13 / SE 时代的屏幕高度**，写死之后就成了一份会过期的镜像。
- 实测（Chromium 真跑，不是估算）：

  | 设备 | 视口 | 上下留边 |
  |---|---|---|
  | iPhone 15 | 393 × 852 | 8px |
  | iPhone 15 Pro Max | 430 × 932 | **88px** |
  | iPhone 16 Pro Max | 440 × 956 | **112px** |
  | Pixel 8 | 412 × 915 | **71px** |

  而且露出来的是 `#d9ccb1`（桌面「手机框」外的底色），和纸色 `#faf3e2` 不同，所以特别显眼。
- **修法**：`@media(max-width:699px)` 下铺满 `100vw × min(100svh, 100vw*2.5)`，去掉左右黑边与投影，
  底色改成纸色。`≥700px` 的桌面手机框造型原样保留。
- **顺带发现**：现代手机的长宽比几乎正好是本作的设计比 844/390 = 2.164——
  iPhone 15 Pro Max 是 932/430 = 2.167。**铺满之后反而比原来封顶时更不变形**
  （原来 Pro Max 上是 -9.3% 的纵向压缩，现在是 +0.2%）。那个 844 封顶是纯粹的损失。
  2.5:1 的收口只对超长安卓设备生效，那种情况下露出来的边也是纸色，看不出来。
- 三个安卓宽虚拟视口的兜底路径（`html.wide-mobile-viewport`）必须保持固定盒再整体缩放，
  所以给它加了一条更高优先级的规则把固定盒还回去，别被铺满规则带偏。已实测 980×2048 下外框仍是 960×1761。
- **iPhone 上还有一个不是代码的坑**：只有 **Safari** 的「添加到主屏幕」才产生独立全屏应用；
  Chrome / Edge / 微信内置浏览器加出来的只是书签，点开仍带地址栏，用户会以为是游戏没做全屏。
  安装说明页现在第一条就写这句，并且检测到 iOS 上的非 Safari 浏览器时会直接点破。
- 四条门禁已加并反向验证：铺满规则本身、PWA 全屏声明、安全区声明、安卓宽视口固定盒。
  改回 844 封顶、删掉任一条声明，构建都会失败。

**红鲤鱼帽重画**

我上一轮加的「自检入口必须被调用」断言写的是 `html.includes(fn + '(')`——
**被函数定义自己满足了**，把三个自检的调用点全删光照样出包。
修的时候又踩第二层：改成数带括号的调用仍然不对，因为 `setTimeout(runQA,50)`

**以后加门禁，一律当场反向验证一次**：故意把它该拦的东西弄坏，看它是不是真的红。
这一条现在是本作的硬规矩，本次新增/修改的每一道门都照做了。

### 2026-08-13（夜）· Claude · 一个假 bug 的三次误判，比真 bug 更值得记

排查报上来一条「高」：**传真科的台子一踩就碎、碎了不再生，摔回去就永久卡死——
既上不去也摔不死，这一局永远不结算**。听起来完全说得通（fax 台确实是落地 150ms 后 `alive=false`，
而 `generatePlatforms` 只往上加、不补下面），我差点就动关卡生成器了。

**它是假的。** 我查了三次才查对，三次错法各不相同，都值得记：

1. **第一次：用例自己造出了游戏里不存在的状态。** 我把猴子瞬移到 610 米再手动
   `generatePlatforms`，25 局里「卡住」1 局。可 `resetWorld` 之后世界是从 baseY 长出来的，
   瞬移打乱了路线锚点——那个洞是我自己挖的。
2. **第二次：判据选错了字段。** 改成正常开局，用「`maxMeters` 连续 25 秒不涨」当判据，
   30 局里中了 2 局。但 **`maxMeters` 只增不减**：玩家从峰值掉下来、正在往回爬，
   这个数当然不涨——那是正常游戏，不是卡住。
3. **第三次才对：判据要看「当前高度在一段时间里的活动范围」。** 24 秒窗口内上下活动
   不到 25 米才算卡住。结果：**30 局 0 卡住**，最窄的活动范围也有 26 米，中位 712 米。

顺手把「那两局到底怎么回事」也算清楚了：站在那一带任意一块台上弹起来，
实际还够得到高出 300~396 的台（靠香蕉板/险字台的高弹力）；seed 29 那局头顶最近的台
干脆只高出 103——**普通一跳 136 就够得着**。所以既不是死路，连难都算不上。

真正的原因是**自动驾驶的搜索窗口写死 158**，而各类台的弹力换算成升高是：
普通 680->136、险字 825->200、审讫 930->254、香蕉板 955->268。窗口比实际能跳到的还矮，
于是它看不见高弹力的台，站在原地干弹。我试着按最高弹力把窗口放到 275 再量了一次：**40 局中位高度 2081 -> 2113，其余指标基本不动**——
是噪声不是改进。所以**撤回了**，代码维持 158，只把结论写进注释。
不为一个不影响结果的小别扭去动 `?stress=1` 依赖的代码，这也是一条：
**改动要有量出来的理由；量完发现没用，就撤掉，别留没根据的改动。**

**给下一个接手的三条**：
- **自动驾驶卡住 ≠ 关卡有死路。** 下结论前先算一遍「从这一带任意一块台弹起，够不够得到更高的台」。
- **判据用错字段，比没有判据更能骗人。** 单调只增的量（`maxMeters`、累计计数）不能用来测「有没有停滞」。
- **能在真机复现 ≠ 复现的是真问题。** 用例里手动改 `state`、瞬移角色、跳过生成流程，
  都可能造出游戏里根本达不到的状态。这也是这次排查里给证伪方写的那条要求：
  「特别注意：用例里自己制造了不可能的状态，就说游戏有问题」。我自己先踩了。

这两条是排查里报上来、我判断**属于既有问题而不是这次改动引入**的，也没有独立复核过

### 2026-08-13（深夜）· Claude · 结算导航改人性化（附一条形同虚设门禁的现场）

王老师原话：「那个下一页下一页，在一些场景中，比如结算还有主页问题上不够灵活……
我们的确限制在一个屏幕、不要上下滚动，但是目前这个会不够人性化在部分习惯性场景」。

**先量，再改。** 量出来的事实比「翻页手感不好」严重得多：

| 视口 | 结算卡片高 | 屏高 | 卡片外空着 | 三页内容合计 |
|---|---|---|---|---|
| 390x844 | 384 | 844 | **460px** | 885px |
| 320x568 | 355 | 568 | 214px | 829px |

也就是说：**屏幕空着近一半，内容却被切成三页盲翻**。分页当初是防溢出加的，
但没人量过到底有没有溢出。（三页合计 885px 确实塞不进一屏，所以分页本身没错，
错的是「用线性翻页去导航三个互不相同的页面」。）

**更硬的一条：结算页根本没有回首页的路。** 穷举过结算上所有可点的东西——
再来一局（直接开局）、生成成绩海报、登记、查看世界楼榜 / 称号墙 / 奶茶图鉴、上一页、下一页——
没有任何一条能回到 `#titleScreen`。而开工装备、本局轮值、档案章数、添加到桌面
全都只长在首页上。**玩过一局之后，这些东西就再也够不着了，除非重新载入页面。**
`showTitleScreen` 全仓库只有四个调用点，全都进不来结算这一屏。

**改了什么**

- 上一页/下一页 -> 三个命名标签（成绩 / 本局档案 / 登记收藏）。
  线性翻页的毛病不是慢，是**把去处藏了起来**：玩家不知道下一页有什么，就没有理由点。
- 标签红点：这一局真解锁了东西才亮。**第一版写坏了**——判据用「teaOrder 有没有字」，
  而它每局都有字（没开出新的也会写一句「没开出新的」），于是红点每局都亮。
  **一个永远亮着的红点等于没有红点**，玩家两局就学会无视它。现在用 `state.freshTeaCount`。
  「登记收藏」的点只在还没登记过化名时亮——登记过之后正式局是自动补交的，再催就是噪音。
- 左上角「返回首页」，与右上角编号牌对称，**不占任何竖向空间**（这一屏竖向预算紧，
  回家的路不该跟内容抢地方）。它必须清 `state.over`，否则子屏幕的返回键会把玩家又弹回结算。
- 再来一局 / 生成成绩海报移到三页共用。核心循环是「摔了再来」，这颗按钮不该会消失。
- 页码点：占的是原来「1 / 4」那一格，**不新起一行**。第一版让它单独占一行，
  320x568 上把奶茶图鉴顶出去 26px——一个纯便利功能不该拿走内容的高度。
  页数超过 `DOT_PAGER_MAX`（6）退回文字，否则中间那一格会被撑爆。
- 左右滑动、左右方向键都能翻页，全部走同一个 `stepPage`。
  两套写法迟早出现「滑得到第 4 页、按钮只到第 3 页」。
  滑动只挂在菜单屏上（游戏进行中它们是 hidden，`activePager()` 返回 null，不抢操作手感）。
  **实测过一个风险**：从「再来一局」按钮上横滑会不会既翻页又开局？用 CDP 发真触摸事件测的，
  横移 120px 后 Chromium 取消了 click，没有误开局。所以没加「不许从按钮上起滑」的限制——
  加了反而会让手势在按钮密集的下半屏失效。
- Esc 改走统一的 `activeMenuClose()`。原来那里手抄了三个子屏的判断，安装页与分享页漏在外面。
- 子屏返回文案说实话：从结算进去的写「返回本局结算」，不再谎称「继续上楼」。

**320x568 满档案时首页溢出 40px（真 bug）**

根因不是屏幕小，是**卡片高度会随档案内容增长**：`称号 · 专业坠落员（MYSKME 认证）`、
`在喝 · 红鲤鱼冰萃（仿的）` 这种按钮文案一换行就多一行。改成单行截断，
再补一段 `max-height:620px` 的收紧。**卡片是 `overflow:hidden`，溢出的部分不是能滚，
是直接看不见**——玩家只会觉得「最高分那一行没了」，不会觉得「有东西被裁了」。

**这一次最值得记的：一条形同虚设的门禁，让所有人都以为查过了**

原来守「单屏不滚动」的自检写的是：

```js
getComputedStyle(el.title).overflowY==='hidden' && typeof renderPager==='function'
  && document.querySelectorAll('.result-page').length===3
```

三个恒真的条件。**当场反证**：往首页卡片里塞一个 4000px 的空 div，卡片溢出 3822px，
这条自检照样绿。所以 Codex 报「桌面与手机逐屏实测溢出均为 0」不是他测错——
是这条门根本没在守它声称守的东西，而 320x568 满档案那 54px 就这么漏过去了。

现在改成真量：拿**最坏情况的档案**（全称号、全奶茶、最长的称号名与奶茶名、意外与窗景收满）
逐屏逐页量 `scrollHeight - clientHeight`。空档案量不出问题，这也是原来漏掉的原因。

**门禁分两层，各管一段**：构建期（CI 会跑）守结构，运行期 `?qa=1` 守行为。
这次新增/改动的每一道门都做了反向验证，其中数引用次数那条**连踩两层**：

1. 第一版写 `/data-page-step/`，被自检自己的 `querySelector('[data-page-step]')` 满足了。
   改成匹配真正的属性写法 `data-page-step="`。
2. 改完再数 `bindSwipePaging` 的引用次数，又被自检里的 `.toString()` 那句满足了——
   把真正的接线整行删掉，门照样绿。**修法：数之前先把自检代码整段切掉，只数产品代码。**

判据留在这里：**检测器和检测目标同形，就是一道假门。**
加门禁一律当场反向验证，而且要验「删掉接线」这种最像样的破坏，不要只验「删掉函数」。

**顺带修好了自己的验收脚本**

`play.mjs` 与 `tea-test.mjs` 从 PR 41 分页那天起就一直是红的，没人发现——
它们直接点 `#resultTitlesButton`，而那颗按钮在结算第 3 页、默认 `display:none`。
先拿 Codex 未改动的 `20260813.8` 跑了一遍确认同样红，才敢说不是本次改动引入的。
**一套会静默过期的验收脚本，和一条不会失败的门禁是同一类问题。**
现在两个脚本都改成按命名标签走位，顺带也就测到了新导航；
奶茶那条改成翻遍所有页再数杯子（原来在一页上数 20 个，分页后当然只有 4 个）。

### 2026-08-13（深夜）· Claude · 世界楼榜的退出键会被别人的化名裁掉（并加多视口验收）

并行巡查报上来的一条「高」，**在真机上是死路**：

320x568（iPhone SE 一代 / 5s）打开世界楼榜，只要榜上任何一行的化名到了 8 个字以上，
行就换成两行，五行一起把卡片顶爆 51px。卡片是 `overflow:hidden`，
**被裁掉的正好是「看完了，继续上楼」那颗唯一的退出键**——而手机上没有 Esc。
玩家只能杀进程或刷新，刷新前本局的登记入口也一起没了。

三个点特别值得记：

1. **触发条件不是自己造成的。** 化名上限就是 12（`#rankName maxlength`），
   只要**别人**填了长名字，所有小屏玩家一起中招。自己怎么玩都躲不开。
2. **桌面上永远测不出来。** 电脑有 Esc，而且 1280x720 根本不溢出。
3. **跟首页那两颗按钮是同一条病**：卡片高度随内容增长。
   首页是自己的称号名/奶茶名变长，榜单是别人的化名变长，根因一样。

**改了什么**：榜单行的化名与来源改成单行截断；另外给榜单补了一颗角落返回键
（和结算那颗同款），因为**唯一的出口不该是卡片里最后一个普通流内子元素**——被裁了就等于没有。

**这条暴露了我自己那道新门禁的两个洞，两个都补了**

- **洞一：漏了屏。** 我写的 `measureMenuOverflow` 只量了首页、结算、称号墙、奶茶，
  **没量世界楼榜**。补上了，而且喂的是 12 字化名 + 三个口径各量一遍——
  行高是被别人的名字决定的，不喂最长值等于没量。
- **洞二：漏了视口，这个更要命。** 补上榜单之后，那条自检在 390x844 上**照样是绿的**，
  因为那个视口有富余。也就是说：一条只在宽屏跑的门禁，和一条永远不会失败的门禁是同一类东西。

  修法是新增 `monkey/tools/qa-viewports.mjs`：在五个视口上各跑一遍 `?qa=1`，
  任何一个红就退非零。反向验证过——把化名截断那行拿掉：

  ```
  [败] 320x568  FAIL 单屏菜单在满档案下溢出：世界楼榜(weekly) 超出 51px、(alltime) 51px、(effort) 51px
  [过] 360x800 / 390x844 / 430x932 / 1280x720
  ```

  **只有最小的那个红**——这就是为什么它以前漏得掉。

  视口清单里每一条都写了它代表什么，别当成随手挑的数字在某次「顺手清理」里删掉最小那个：
  最小那个正是唯一会出事的那个。CI 里没有浏览器，所以这一步是收工前手动跑的；
  构建门禁守结构，它守「小屏上放不放得下」。

**为什么放在仓库里而不是会话的临时目录**：上一轮的验收脚本（`play.mjs` / `tea-test.mjs`）
就躺在临时目录里，PR 41 加分页之后它们静默红了一整天没人发现。
**会过期的验收脚本，和不会失败的门禁，是同一个问题的两面。**

**顺带一条方法**：巡查 agent 发现主会话正在改 `monkey/index.html`，
自己用 `git archive origin/main` 取了一份只读快照再测，并在报告里注明哪些结论来自快照、
哪些在工作区版本上复现。多 AI 并行时这是必须的——否则「审的是哪一版」根本说不清。
