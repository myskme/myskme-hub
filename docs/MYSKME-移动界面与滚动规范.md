# MYSKME 移动界面与滚动规范

本规范用于网页游戏、微信小游戏迁移版、作品启动台和学习工具。目标不是“全站禁止滚动”，而是让滚动只出现在它真正有助于理解的地方。

## 一、三种页面模式

### A. 固定视口应用

适用：游戏主界面、棋盘、作品启动台、计分器、高频控制台。

- 外壳使用动态视口高度，页面本身不滚动、不回弹、不下拉刷新。
- 主要操作、状态和返回路径必须在首屏内完成。
- 短屏按顺序处理：删除装饰占位 → 收起次要说明 → 改为分页或弹层 → 最后才允许指定面板滚动。
- 不用把整个界面缩到难以阅读；核心按钮目标尺寸以 44×44 CSS px 为优先基准。
- 背景可延伸到屏幕边缘，文字、按钮、拖拽区必须避开安全区域和系统手势区。

当前归类：

- 作品总目 `index.html`
- 《灵石远征》`match/index.html`
- 每日一题的单题操作态 `daily/index.html`

### B. 固定外壳 + 内部滚动

适用：排行榜、图鉴、行囊、设置、历史记录和长帮助。

- 页面外壳不动，只有一个职责明确的内容面板滚动。
- 面板需设置滚动边界，避免滚动继续传递给宿主页面。
- 关闭、返回、确认等关键操作保持可见，不能要求用户滚到底才能退出。
- 长名单提供搜索、筛选、分页或分组，不能只靠无限向下拖动。

当前归类：

- 《灵石远征》的远征榜、典藏、生涯、行囊、挑战和玩法说明弹层
- 授业历的周视图和表单弹层
- 管理后台中的长列表与编辑面板

### C. 自然阅读页面

适用：作文墙、文章、题库目录、长题干、写作编辑、打印预览和说明文档。

- 保留浏览器原生纵向滚动、选择文本和阅读进度。
- 标题、筛选或主要操作可以按需吸顶，但不锁死整页。
- 弹层打开时才临时锁住背景滚动；关闭后恢复原位置。
- 手机采用单列阅读，避免为了“一屏”把文字、图片或输入区缩小。

当前归类：

- 优秀作文墙 `wall/index.html`
- 题库书架 `banks/index.html`
- 听力训练场 `listen/index.html`
- 作文训练场 `write/index.html`
- 打印中心 `print/index.html`
- 命题铸炉与出题工坊中的长表单、结果和说明

## 二、判定问题

遇到新页面时依次回答：

1. 用户的核心任务是否需要持续操作同一块画面？是，则优先 A。
2. 长内容是否只是辅助信息、名单或设置？是，则优先 B。
3. 用户是否需要连续阅读、比较、输入长文本或保留阅读位置？是，则采用 C。
4. 如果一屏放不下，是否能先移除装饰和重复说明？能，就不要缩小全部内容。
5. 如果仍放不下，能否拆成分步、分页或弹层？能，就不要让主界面变成长网页。

## 三、验收门槛

- 设备：至少检查 `390×844`、`320×568`、平板和桌面。
- 固定视口：文档高度等于可见动态视口，不出现页面级纵向或横向滚动。
- 阅读页面：不得横向溢出；返回、筛选和重要操作不得被固定控件遮挡。
- 触控：主要操作按 44×44 CSS px 设计；紧凑次级控件也要保持清楚、分隔充分。
- 字体：不以全屏缩放解决布局；最小辅助文字仍需可辨，正文不因短屏被压成缩略图。
- 安全区：顶部、底部和侧边操作避开刘海、圆角、系统返回与手势区域。
- 状态：软键盘、地址栏伸缩、横竖屏和分屏变化后重新计算布局。
- 无障碍：键盘焦点、减少动态效果、颜色之外的状态提示都要保留。

## 四、参考原则

- [Apple Human Interface Guidelines — Designing for games](https://developer.apple.com/design/human-interface-guidelines/designing-for-games/)
- [Apple Human Interface Guidelines — Layout](https://developer.apple.com/design/human-interface-guidelines/layout)
- [Android Developers — Edge-to-edge design](https://developer.android.com/design/ui/mobile/guides/layout-and-content/edge-to-edge)
- [web.dev — Large, small, and dynamic viewport units](https://web.dev/blog/viewport-units)
- [MDN — overscroll-behavior](https://developer.mozilla.org/docs/Web/CSS/overscroll-behavior)

这些规范共同指向同一结论：沉浸式界面应充分利用屏幕并尊重安全区域，但长内容必须保留清晰、可预期的滚动方式；一致性来自任务逻辑，而不是让所有页面都采用同一种滚动方式。
