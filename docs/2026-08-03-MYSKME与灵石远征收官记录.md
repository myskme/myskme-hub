## 二、长期域名架构

`myskme.com` 是“狼先生与学生们”整个原创世界的总入口，不属于任何单一游戏。
`play.myskme.com` 继续作为《灵石远征》的稳定入口，不因将来建立作品大厅而迁址。

后续作品按独立身份使用稳定子域：

- 自鸣棋：建议 `zimingqi.myskme.com`
- 笼中剑：建议 `blade.myskme.com`
- 将来的统一游戏大厅：可放 `games.myskme.com` 或 `myskme.com/play/`

子域名本身不是稀缺资源。PWA 作用域、浏览器本地存档、排行榜来源、二维码与玩家记忆
才是需要保持稳定的资产，因此不要为了“统一”频繁移动已经上线的作品地址。

## 三、国内链路与数据权威

- 国内用户优先通过腾讯云 DNSPod、EdgeOne 与同源入口访问。
- 前端可以经 `play.myskme.com` 的腾讯云/EdgeOne 服务转发请求。
- 现有 Cloudflare Worker 与 D1 继续作为唯一权威后端。
- 不迁移数据库、不双写，也不为内测榜单保留而牺牲未来链路稳定性。
- 旧内测成绩必要时可以重置；新架构以可靠上传、可诊断和后续扩展为先。

## 四、图标与 PWA 身份

- `myskme.com` 使用狼先生侧面肖像作为品牌主屏幕图标。
- `play.myskme.com` 使用金曜六边形灵石与小矿灯作为《灵石远征》图标。
- 将来每个独立游戏都应拥有自己的图标、Manifest、启动身份与子域，不能把品牌图标和游戏图标混用。
- iOS 会长期缓存主屏幕图标；换图后应删除旧快捷方式，再从 Safari 重新“添加到主屏幕”。

## 七、以后继续开发时的硬边界

1. 不把《灵石远征》从 `play.myskme.com` 搬走。
2. 不把品牌狼先生图标替换成单一游戏的宝石图标，也不反向混用。
3. 不迁移或双写 D1；如将来更换数据库，必须另立迁移方案和回滚点。
4. 不手改 `match/ports/ios-capacitor/www/` 或微信同步生成的资源副本。
5. 网页、iOS、微信小游戏共享纯逻辑与资源总账，但平台 API、渲染和发布包必须分层。
6. 正式发布前至少检查：自检、资源引用、移动端布局、PWA 元数据、弱网提交与线上域名。
